# Введение


Микродрон — учебный квадрокоптер нового поколения, позволяющий реализовывать такие задачи, как визуальное управление, автономный полёт и обучение нейронных сетей для оптимизации принятия решений.


Набор включает в себя полётный контроллер на PX4, бортовой компьютер, камеру и датчик оптического потока.

Бортовой компьютер;

Камера;

-

Датчик оптического потока.

# Предустановка программ и файлов


**Шаг 1. Установка программного обеспечения**


Для дальнейшей настройки и работы с микродроном установите следующие программы:

-

[QGroundControl](https://docs.qgroundcontrol.com/master/en/qgc-user-guide/getting_started/download_and_install.html) — программное обеспечение для настройки и калибровки полётного контроллера. При установке дайте **согласие на установку** дополнительных драйверов.

-

SSH-клиент на ОС Windows (например, [mRemoteNG](https://mremoteng.org/)) для подключения к бортовому компьютеру и работы с нейросетью. Для macOS и Linux — Terminal (встроен в систему).

Создайте на рабочем столе папку, например, «Микродрон», и сохраняйте все файлы в неё.

[Файл с параметрами](https://drive.google.com/drive/folders/1aVPsCSyAKYzgZ8UkZjKGdlTMvxZDnppT?usp=drive_link) полётного контроллера.

**Примечание** Бортовой компьютер микродрона поставляется с предустановленным образом. Если потребуется переустановка — см. [Установка образа](/learn/whoop/kb-image).

# Сопряжение пульта с микродроном


>

**Примечание** Если хотите настроить русскую озвучку и загрузить профиль настроек — см. [Настройка озвучки RadioMaster Pocket](/learn/whoop/setup-controller-voice).


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fsetup-controller%2Fimage12.png&sig=8e372d2e6a1bc5de8a5bc3a4ebd887752ce242ccf01d85e5a2c72bb3c8e7e207)



**Binding Phrase** — это общая кодовая фраза, которая связывает передатчик (TX) и приёмник (RX). Они должны содержать одинаковую фразу, чтобы найти друг друга и установить связь.


Сопряжение выполняется через одинаковую **Binding Phrase** на аппаратуре управления (передатчике TX) и микродроне (приёмнике RX).

## Подготовка аппаратуры управления

- Снимите чёрные резиновые накладки с задней стороны аппаратуры управления.
- Вставьте [АКБ](/learn/whoop/kb-battery), соблюдая полярность.
- Переведите все стики и переключатели в исходное положение:
  - Левый стик — вниз.
  - Тумблеры **SB**, **SC** — от себя.
  - Переключатели **SA**, **SD** — в положение выкл.

![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fsetup-controller%2Fimage25.png&sig=7d49a3deb370be8336f6f4dcb85e2a9cadab1614b75fc51de047de2767186b90)


-

Подключите зарядное устройство через порт USB Type‑C и оставьте подключённым (можно использовать во время полётов).

-

Включите аппаратуру управления — зажмите **кнопку питания** до появления на экране 4-х точек.


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fsetup-controller%2Fimage26.jpg&sig=13e882d8cbe4efdf842e5df9a71d068520ce2a8eae4cf6996987f727810bd70f)

**Подсказка** Если при включении на экране появляется предупреждение — перепроверьте положение стиков и тумблеров.

# Подключение по проводу


Подключение к бортовому компьютеру выполняется по протоколу SSH через кабель USB Type-C. IP-адрес микродрона при проводном подключении всегда фиксирован: `10.10.1.1`. Логин и пароль — `root`.


>

**Подсказка** Проводное подключение надёжнее Wi-Fi и рекомендуется для первоначальной настройки и отладки.


Для подключения потребуется SSH-клиент. Варианты по операционным системам:


**Linux**

- OpenSSH Client
- Linux Terminal

**Windows**

- PuTTY
- mRemoteNG
- SecureCRT

**macOS**

- Terminal
- ZOC Terminal

## Подключение через Terminal (Linux / macOS)


Выполните команду:


```
ssh root@10.10.1.1

```


## Подключение через mRemoteNG (Windows)

- Выберите протокол **SSH2**.

![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fsetup-wire%2Fimage2.png&sig=fe2b72d95534a6a859e62a346922766443352f7c5fe6f29b9069078dd87f2c86)


- В строке «подключение» введите IP-адрес: `10.10.1.1`.

![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fsetup-wire%2Fimage1.png&sig=80005d971ff2f0259acd7113be0be7f32f7e351bb0d7dbad4beca83e75cffb68)


- Введите логин и пароль (`root` для обеих строк).

![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fsetup-wire%2Fimage3.png&sig=53eff7b5007fce2386eca28684c7533719769cc749ef54bf7a0a01234eb8abca)



>

**Примечание** Для подключения к QGroundControl через USB-кабель — см. [Подключение к QGroundControl](/learn/whoop/kb-qgc).

# Подключение по Wi-Fi


Для беспроводного подключения нужно прописать данные вашей Wi-Fi сети в конфигурационный файл на бортовом компьютере микродрона. Это делается через [проводное подключение](/learn/whoop/setup-wire) по SSH.


>

**Примечание** Компьютер и микродрон должны быть в одной Wi-Fi сети.

- Откройте конфигурационный файл управления беспроводными сетями:

```
nano /etc/wpa_supplicant.conf

```


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fsetup-wifi%2Fimage1.png&sig=1ebff7df96335488b580f708e109f2e30fe96824fa2b47b8f366367f149cc55c)


- Пропишите **имя сети** и **пароль**:

```
network={
  ssid="ИМЯ СЕТИ"
  psk="ПАРОЛЬ"
}

```


>

**Внимание** Имя сети и пароль не должны содержать кириллицу.

- Определите **тип безопасности** сети:

![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fsetup-wifi%2Fimage3.png&sig=0437f7c48d66ba57d61013424971305517ad7f35427b65239ec855137d45857a)



![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fsetup-wifi%2Fimage2.png&sig=2fdde1cd7e71b5e300d78002f6b73e70ce98de973264e7540af6ff632725c081)


- Допишите строки в зависимости от типа сети:

**WPA/WPA2**


```
network={
  ssid="ИМЯ СЕТИ"
  psk="ПАРОЛЬ"
  key_mgmt=WPA-PSK
  proto=WPA RSN    # WPA и WPA2
  pairwise=TKIP CCMP  # шифрование TKIP и AES
  group=TKIP CCMP
}

```


**WPA2**


```
network={
  ssid="ИМЯ СЕТИ"
  psk="ПАРОЛЬ"
  key_mgmt=WPA-PSK
  proto=RSN        # только WPA2
  pairwise=CCMP    # только AES
  group=CCMP
}

```


**WPA2/WPA3**


```
network={
  ssid="ИМЯ СЕТИ"
  psk="ПАРОЛЬ"
  key_mgmt=WPA-PSK-SHA256 SAE
  proto=RSN
  ieee80211w=1
  pmf=optional
}

```


**WPA3**


```
network={
  ssid="ИМЯ СЕТИ"
  psk="ПАРОЛЬ"
  key_mgmt=SAE
  proto=RSN
  ieee80211w=2
  pmf=required
}

```

-

Сохраните файл: **Ctrl+X → Y → Enter**.

-

Подключитесь к Wi-Fi:


```
wpa_supplicant -Dnl80211 -iwlan0 -c/etc/wpa_supplicant.conf

```

## Настройка полётных режимов


Во вкладке **Flight Modes** настраивается соответствие позиций переключателя **SB** режимам полёта, а также Arm и Kill Switch.


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fsetup-rc%2Fimage8.png&sig=b1e9ca71da565fc1e9adab79e43b8f8e8f83a07655375c085135118f73e46f81)



Настройка полётных режимов (поле **Flight Mode Settings**):

- **Mode Channel** → **Channel 6** (переключатель SB)
- **Flight Mode 1** → **Stabilized**
- **Flight Mode 4** → **[Position](/learn/whoop/manual-flight-position)**
- **Flight Mode 6** → **Altitude**

>

**Внимание** Жёлтым подсвечивается режим, соответствующий текущей позиции переключателя **SB**.


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fsetup-rc%2Fimage9.png&sig=33231724272682a9a12a1e7ebcde9b5252d8548bc2f84457e96a44e17e90d768)



Настройка переключателей (поле **Switch Settings**):

# Основы ручного пилотирования


Управление микродроном происходит с помощью двух стиков аппаратуры управления. По умолчанию **левый стик** отвечает за газ и рысканье, а **правый стик** за крен и тангаж. Данные термины используются для всех летательных аппаратов, от самолётов до квадрокоптеров.


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fmanual-flight%2Fimage6.png&sig=4569941aca34131ab38900786a40ba30911dd73d6e09203291488c935e603c50)



![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fmanual-flight%2Fimage3.png&sig=1759e63d12d478b8e62912255c80b2d37959a38292e7408e9f875e339d70560b)



**Газ (throttle)** — отвечает за скорость вращения двигателей.


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fmanual-flight%2Fimage4.png&sig=7d980939c37cf8a7135b1d2df28329b42151c70c829556bc8906c7fb4c1f305e)



**Рысканье (yaw)** — отвечает за повороты вокруг вертикальной оси (Z), смещение стика вправо (влево) приводит к вращению по (против) часовой стрелки.


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fmanual-flight%2Fimage2.png&sig=cab19e6588602eda03ee2c2a8fbbd17d775be560bf85a9ef51175b468c479874)



**Тангаж (pitch)** — отвечает за наклон или движение вперёд/назад.


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fmanual-flight%2Fimage1.png&sig=573dae6afc49a47990c13163e3620d25e0bad11b614814b23222e96adfe370c3)



**Крен (roll)** — отвечает за наклон или движение влево/вправо.


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fmanual-flight%2Fimage5.png&sig=7cfbd2b43d412f3e66059a86f83c59c78fb964dd81f4b3e383637098ab206376)



>

**Примечание** Все описанные действия микродрона подразумеваются относительно его ориентации в пространстве.


**Визуальный полёт (ручное управление)**


При визуальном пилотировании оператор управляет дроном напрямую.


**Режимы полёта:**


>

**Примечание** Действия стиков **Yaw**, **Pitch** и **Roll** в полётных режимах одинаковы: поворот, наклон вперёд-назад и влево-вправо.

- **STABILIZED** — стабилизация горизонтального положения, необходимо **ручное поддержание высоты**

>

**Примечание** **Throttle** — управление газом из нижнего положения стика. При возврате правого стика в центральное положение микродрон выровняется, но продолжит движение по инерции и под воздействием внешних сил.

- **ALTITUDE** — удержание высоты

>

**Примечание** **Throttle** — управление газом из центрального положения стика, отвечает за скорость подъёма/спуска. При возврате обоих стиков в центр микродрон выровняется и будет удерживать текущую высоту, но продолжит движение по инерции и под воздействием внешних сил.

- **[POSITION](/learn/whoop/manual-flight-position)** — полное удержание положения в пространстве и компенсации воздействия внешних сил.

>

**Примечание** **Throttle** — управление газом из центрального положения стика, отвечает за скорость подъёма/спуска. При возврате обоих стиков в центр микродрон зафиксируется в точке пространства, компенсируя ветер и другие силы.

## 13. Полёт в режиме POSITION
`manual-flight-position` · https://edu.sverk.tech/learn/whoop/manual-flight-position

# Полёт в режиме POSITION


>

**Внимание** Обязательный шаг перед первым запуском автономного полёта.


Режим POSITION удерживает микродрон в фиксированной точке пространства — компенсирует ветер и инерцию. При отпускании стиков микродрон зависает на месте. Это необходимо для стабильного автономного полёта.

- Включите аппаратуру управления.
- Переведите левый стик вниз, а правый — в центральное положение.

![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fmanual-flight-position%2Fimage7.png&sig=1a7f9e4b7d0153cefacc85e65f5470550fd6883d37bb3a71d6a5f2e6634f2398)


- На аппаратуре управления переведите переключатель **SB** в положение **Position** (как было настроено в разделе [Калибровка аппаратуры управления](/learn/whoop/setup-rc)).

![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fmanual-flight-position%2Fimage4.png&sig=4ec919530699ca9786e2bf672731078f8dde24e2b2ee843b6a255eb624318cf3)


-

Установите микродрон на точку взлёта.

-

Подключите [АКБ](/learn/whoop/kb-battery) к микродрону.

-

Дождитесь полного включения микродрона.

-

Отойдите от микродрона.


## Взлёт


Кнопки управления:

- **SA** — Arm/Disarm (включение/отключение моторов)
- **SB** — выбор режима полёта
- **SD** — Kill Switch (экстренное отключение моторов)

>

**Внимание** Убедитесь, что кнопка **SD (Kill Switch)** отжата.


Нажмите и отпустите кнопку **SA (Arm)** — моторы начнут вращаться на минимальных оборотах.


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fmanual-flight-position%2Fimage5.png&sig=cd08b5fc4c6ddbca3b2f753bab6bc4342fbc48193b1ef7d77581c89ff444a2bc)



>

**Внимание** Кнопка должна заблокироваться в нажатом положении.


Плавно поднимите **левый стик** (Throttle) вверх. Микродрон взлетит и автоматически зависнет на высоте ~1 метра.


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fmanual-flight-position%2Fimage2.png&sig=bcaaa238440d6c26e2a1804ce81abc103e5dc6ef309b9ca25f6f467905d3180e)



Попробуйте немного подвигать **правым стиком** (Pitch/Roll) — микродрон будет двигаться в пространстве, а при отпускании стика снова зависать на месте.


>

**Внимание** Не улетайте слишком далеко от точки взлёта, чтобы микродрон уверенно удерживал позицию.


## Посадка и выключение

- Для посадки плавно опустите **левый стик** (Throttle) вниз до полной посадки микродрона.
- Нажмите и отпустите кнопку **SA (Disarm)**.

>

**Внимание** Кнопка должна выйти из заблокированного положения.

- В целях безопасности нажмите и отпустите кнопку **SD (Kill Switch)**.

>

**Внимание** Кнопка должна заблокироваться в нажатом положении.

- Отключите АКБ от микродрона.
- Выключите аппаратуру управления.

# Предполётная проверка


Перед каждым полётом необходимо выполнить автоматическую проверку корректности настроек и работы всех подсистем микродрона.


Подключитесь к микродрону по SSH и выполните команду:


```
drone selfcheck

```


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fcheck%2Fimage1.jpg&sig=cb66333c37d2cd0ee0fa2a1d8cafdff0ead5925fa75ba779f67de76621ee2cb9)



Что проверяется:

- **FCU** — соединение с полётным контроллером;
- **gyro** — гироскоп;
- **accelerometer** — акселерометр;
- **magnetometer** — магнетометр;
- **gps** — глобальная позиция;
- **vision position** — оптическая навигация;
- **xy position control** — определение положения в пространстве;

- gyro
- accelerometer
- rc receiver

Если остальные ключевые пункты показывают FAIL — **взлёт запрещён!** Выполните [калибровку датчиков](/learn/whoop/setup-calibration).

## 15. Автономный полёт: Python API
`autonomous` · https://edu.sverk.tech/learn/whoop/autonomous

# Автономный полёт: Python API


Автономное управление микродроном реализуется через Python-модуль `simple_offboard_py`. Программы запускаются прямо на бортовом компьютере через SSH.


>

**Внимание** Во время автономного полёта держите аппаратуру управления в руках. При нештатной ситуации переключите **SB** в режим **Position** для перехвата управления, затем посадите дрон вручную.


## Быстрый старт


Подключитесь к микродрону по SSH и создайте файл программы:


```
nano flight.py

```


Минимальный пример — взлёт, зависание, посадка:


```
from simple_offboard_py import SimpleOffboard, Frame

drone = SimpleOffboard()

drone.takeoff(0.7)
print("Взлетел")

drone.land()
print("Сел")

```


Запустите:


```
python3 flight.py

```


>

**Подсказка** Перед запуском убедитесь, что прошла [предполётная проверка](/learn/whoop/check) и микродрон находится в режиме [POSITION](/learn/whoop/manual-flight-position).


## Системы координат


Все методы навигации принимают параметр `frame` — систему координат.


### Frame.BODY_NED


Координаты относительно **текущего положения и курса** дрона.

- X — вперёд по носу, Y — вправо, Z — вниз.
- Удобна для команд «лети вперёд на 1 м» без привязки к карте.

```
# Лететь вперёд на 1 м относительно текущего курса
drone.navigate(1.0, 0.0, -0.7, frame=Frame.BODY_NED, yaw=0.0)

```


### Frame.LOCAL_NED


Координаты относительно **точки взлёта**, оси не вращаются.

- X — на север, Y — на восток, Z — вниз.
- Удобна для навигации по точкам и планирования траекторий.

```
# Лететь в точку (1, 1) на высоту 0.7 м от точки взлёта
drone.navigate(1.0, 1.0, -0.7, frame=Frame.LOCAL_NED, yaw=0.0)

```


>

**Примечание** Ось Z направлена **вниз** — высота 0.7 м над землёй это `z = -0.7`.


## Взлёт и посадка


### takeoff


```
drone.takeoff(height: float = 1.0) -> bool

```


Взлетает на заданную высоту и зависает. Автоматически переводит контроллер в offboard-режим и включает моторы.


Возвращает `True`, если высота достигнута, `False` при превышении тайм-аута.


```
drone.takeoff(0.7)
print("Взлетел")

```


### land


```
drone.land()

```


Посадка. Блокирует выполнение до касания земли, после чего автоматически выключает моторы.


## Навигация


### navigate — полёт к точке


```
drone.navigate(
    x: float,
    y: float,
    z: float,
    frame: Frame = Frame.LOCAL_NED,
    yaw: float | None = None,
    yaw_rate: float | None = None,
    tolerance: float = 0.1,
    time_limit: float = 10.0,
) -> bool

```


Перемещает дрон к заданной точке и ждёт прибытия. Возвращает `True`, если добрался, `False` при превышении `time_limit`.


**Параметры:**

- `x, y, z` — координаты цели.
- `frame` — система координат.
- `tolerance` — радиус «достиг цели» в метрах (по умолчанию 0.1).
- `time_limit` — максимальное время ожидания в секундах (по умолчанию 10.0).
- `yaw` — курс в радианах; `0.0` — смотреть на север (LOCAL_NED) или вперёд (BODY_NED).
- `yaw_rate` — угловая скорость по рысканью.

>

**Внимание** Нужно задать ровно один из параметров `yaw` или `yaw_rate`. Если оба `None` — команда будет проигнорирована.


### set_velocity — управление по скорости


```
drone.set_velocity(
    vx: float,
    vy: float,
    vz: float,
    frame: Frame = Frame.BODY_NED,
    yaw: float | None = None,
    yaw_rate: float = 0.0,
)

```


Задаёт скорость полёта. Не блокирует выполнение — дрон летит, пока не получит другую команду.


```
# Лететь вперёд на 1.2 м/с
drone.set_velocity(1.2, 0.0, 0.0, Frame.BODY_NED, yaw=0.0)

```


### set_position — непрерывное удержание точки


```
drone.set_position(
    x: float,
    y: float,
    z: float,
    frame: Frame,
    yaw: float | None = None,
    yaw_rate: float | None = None,
)

```


Публикует целевую позицию без ожидания прибытия. Используйте в цикле, когда цель постоянно обновляется (например, слежение за объектом).


## Получение данных


### get_position — текущее положение


```
x, y, z, roll, pitch, yaw = drone.get_position()

```


Возвращает координаты в локальной системе и углы Эйлера в радианах.


### get_detections — обнаруженные объекты


```
for det in drone.get_detections():
    print(det.label, det.score, det.x1, det.y1, det.x2, det.y2)

```


Возвращает список объектов, найденных системой компьютерного зрения. Поля каждого объекта:

- `label` — название класса (например, `"balloon"`).
- `score` — уверенность от 0.0 до 1.0.
- `x1, y1` — левый верхний угол прямоугольника (пиксели).
- `x2, y2` — правый нижний угол прямоугольника (пиксели).
- `class_id` — числовой ID класса.

## Ручное включение моторов


`takeoff()` включает моторы автоматически. Если нужно управлять этим вручную:


```
drone.arm()           # включить моторы
drone.disarm()        # выключить моторы
drone.set_flight_mode(0)  # перевести в offboard-режим

```


>

**Подсказка** Типичный порядок ручного запуска: опубликовать сетпоинты → `set_flight_mode()` → `arm()`.

# Примеры Python-программ


## Взлёт, полёт вперёд и посадка

## Полёт по точкам


Дрон последовательно облетает заданные точки и садится.


```
from simple_offboard_py import SimpleOffboard, Frame

drone = SimpleOffboard()

drone.takeoff(1.0)
print("Взлетели")

# Точки (x, y, z) в системе LOCAL_NED
# Z отрицательный: высота 1 м над землёй = z = -1.0
waypoints = [
    (1.0, 0.0, -1.0),
    (1.0, 1.0, -1.0),
    (0.0, 1.0, -1.0),
]

for x, y, z in waypoints:
    reached = drone.navigate(x, y, z, frame=Frame.LOCAL_NED, yaw=0.0,
                             tolerance=0.15, time_limit=15.0)
    if not reached:
        print(f"Не достиг точки ({x}, {y}, {z}), продолжаю")

drone.land()
print("Сели")

```


## Полёт относительно курса дрона (BODY_NED)


`Frame.BODY_NED` — движение задаётся относительно текущего направления носа дрона. Удобно, когда не важно в какую сторону повёрнут дрон: «вперёд» всегда вперёд по носу.


```
from simple_offboard_py import SimpleOffboard, Frame

drone = SimpleOffboard()

drone.takeoff(0.7)
print("Взлетели")

# Вперёд по носу на 1 м
drone.navigate(1.0, 0.0, -0.7, frame=Frame.BODY_NED, yaw=0.0,
               tolerance=0.1, time_limit=10.0)

# Вправо на 0.5 м
drone.navigate(0.0, 0.5, -0.7, frame=Frame.BODY_NED, yaw=0.0,
               tolerance=0.1, time_limit=10.0)

drone.land()
print("Сели")

```


## Поиск объекта и зависание над ним


Дрон медленно летит вперёд. Как только камера распознаёт нужный объект с достаточной уверенностью — останавливается и зависает на месте.


```
from simple_offboard_py import SimpleOffboard, Frame

TARGET_LABEL = "balloon"  # название объекта из модели

drone = SimpleOffboard()

drone.takeoff(0.7)
print("Взлетели")

drone.set_velocity(0.3, 0.0, 0.0, Frame.BODY_NED, yaw=0.0)

found = False
while not found:
    for det in drone.get_detections():
        if det.label == TARGET_LABEL and det.score > 0.7:
            print(f"Найден: {det.label}, уверенность={det.score:.2f}")
            found = True
            break

# Зависнуть на текущей позиции
x, y, z, _, _, yaw = drone.get_position()
drone.set_position(x, y, z, Frame.LOCAL_NED, yaw=yaw)

drone.land()
print("Сели")

```


Что содержит каждый обнаруженный объект:


```
for det in drone.get_detections():
    print(det.label)    # название: "balloon", "person" и т.д.
    print(det.score)    # уверенность: 0.0 — 1.0
    print(det.x1, det.y1)  # левый верхний угол рамки (пиксели)
    print(det.x2, det.y2)  # правый нижний угол рамки (пиксели)

```

# Компьютерное зрение


Обычная камера на дроне — просто источник видеопотока. Компьютерное зрение превращает этот поток в структурированную информацию: «в кадре есть воздушный шар, он находится в правой части кадра».


Микродрон оснащён бортовой камерой. Изображения с неё поступают на бортовой компьютер, где работает нейросетевая модель. На выходе - список обнаруженных объектов: что найдено, где находится на изображении и насколько модель в этом уверена. Python-программа может использовать эти данные для принятия решений в полёте: зависнуть над объектом, облететь препятствие, посчитать количество предметов.


В этом разделе описано как работает модель обнаружения объектов, как собрать собственный датасет и обучить модель под конкретную задачу.

## 18. YOLO: принцип работы
`neural-yolo` · https://edu.sverk.tech/learn/whoop/neural-yolo
======================================================================

# YOLO: принцип работы


YOLO (You Only Look Once) — семейство нейронных сетей для обнаружения объектов в реальном времени.


Классические алгоритмы обработки изображений анализируют кадр в несколько проходов: сначала ищут области, где может быть объект, затем классифицируют каждую область. YOLO делает всё за один проход — отсюда название. Сеть делит изображение на сетку ячеек и для каждой ячейки одновременно предсказывает:

- **Ограничивающий прямоугольник** — координаты x, y, ширина, высота
- **Класс объекта** — к какой категории относится (человек, машина, кошка и т. д.)
- **Уверенность** — значение от 0.0 до 1.0

Результат одного кадра выглядит так:


```
[
  { "label": "person",  "class_id": 0,  "score": 0.91, "x1": 120, "y1": 45,  "x2": 280, "y2": 310 },
  { "label": "bottle",  "class_id": 39, "score": 0.78, "x1": 400, "y1": 200, "x2": 450, "y2": 290 }
]

```


Через API микродрона это же выглядит так:


```
for det in drone.get_detections():
    print(det.label, det.class_id, det.score, det.x1, det.y1, det.x2, det.y2)

```


## Почему YOLO подходит для дрона

|  Требование |  Почему важно для дрона |  Как YOLO отвечает |
|  Скорость |  Дрон движется — задержка при обнаружении = ошибка позиции |  Один проход по сети вместо нескольких |
|  Компактность |  Слабый бортовой компьютер, нет мощной GPU (графического процессора) |  Nano-версии работают на CPU (центральном процессоре) |
|  Точность |  Ложные срабатывания = неверные решения |  Уверенность для фильтрации |
|  Реальное время |  Решения принимаются на лету |  До 30+ FPS (кадров в секунду) на nano-моделях |


## Версии YOLO

|  Версия |  Особенности |  Для микродрона |
|  YOLOv5 |  Зрелая, большая экосистема, много готовых весов |  Подходит, но старше |
|  YOLOv8 |  Улучшенная архитектура, простой Python API |  Подходит |
|  **YOLO11** |  Последнее поколение, лучшая точность |  **Рекомендуется** |


Для бортового компьютера микродрона используйте **YOLO11n** (nano) — наименьшую и быструю версию в семействе. Более крупные варианты (small, medium, large) значительно медленнее. Эту же версию использует готовый [ноутбук обучения](/learn/whoop/neural-training).


## Интеграция с микродроном

- **Камера** непрерывно снимает видеопоток.
- **Бортовой компьютер** прогоняет каждый кадр через YOLO-модель и находит объекты.
- **Ваша программа** читает результаты через `drone.get_detections()`.
- **Программа принимает решение** — зависнуть, полететь к объекту, продолжать поиск.
- **Отправляет команду** — `drone.navigate()` или `drone.set_velocity()`.

Метод `drone.get_detections()` возвращает текущий список объектов в кадре — каждый объект содержит:

- `det.label` — строковое название класса (например, `"balloon"`)
- `det.class_id` — числовой ID класса
- `det.score` — уверенность (0.0—1.0)
- `det.x1, det.y1` — левый верхний угол прямоугольника (пиксели)
- `det.x2, det.y2` — правый нижний угол прямоугольника (пиксели)
- `det.z1, det.z2` — глубина 3D-бокса (при наличии информации о дистанции)

Для большинства задач достаточно `label`, `score` и координат `x1/y1/x2/y2`.


## Пользовательские классы


Предобученные модели YOLO знают 80 стандартных классов (датасет COCO): люди, машины, животные, мебель и т. д. Для специфических задач — например, обнаружение маркировки на полу или конкретного предмета — нужно обучить свою модель на собственном датасете.


Процесс:

- Собрать изображения объекта с разных ракурсов и при разном освещении.
- Разметить объекты (нарисовать прямоугольник для каждого объекта на каждом фото).
- Обучить YOLO11n на размеченном датасете.
- Скопировать файл модели на бортовой компьютер.

Подробнее — в статьях «[Сбор датасета в Roboflow](/learn/whoop/neural-dataset)» и «[Обучение модели YOLO11](/learn/whoop/neural-training)».


## Разрешение камеры


Бортовая камера микродрона выдаёт видеопоток с разрешением **1280 × 720** пикселей. Центр кадра — точка (640, 360). Это значение важно при вычислении смещения объекта от центра кадра для управления по визуальной обратной связи:


```
FRAME_W, FRAME_H = 1280, 720
FRAME_CX, FRAME_CY = FRAME_W / 2, FRAME_H / 2  # (640.0, 360.0)

# Смещение центра прямоугольника от центра кадра (нормированное, от -0.5 до +0.5)
obj_cx = (det.x1 + det.x2) / 2
err_x = (obj_cx - FRAME_CX) / FRAME_W

```


Координаты (`x1, y1, x2, y2`) всегда приходят в пикселях этого разрешения.


## Ограничения бортового компьютера


Бортовой компьютер — энергоэффективное вычислительное устройство с ограниченными ресурсами. При использовании YOLO учитывайте:

- **Низкий FPS** — 3—10 кадров в секунду при инференсе nano-модели на CPU. Достаточно для медленного полёта, но не для быстрого маневрирования.
- **Только nano-модели** — YOLO11n или аналоги. Более крупные модели будут работать слишком медленно или не запустятся.
- **Уменьшайте разрешение входа** — инференс на 320×320 или 416×416 быстрее, чем на 640×640. Точность немного снизится, скорость вырастет вдвое.
- **Не запускайте тяжёлые фоновые процессы** — во время инференса бортовой компьютер должен иметь максимально свободные ресурсы.

Для задач, где требуется высокий FPS, рассмотрите аппаратное ускорение (ONNX Runtime с оптимизациями под архитектуру платы) или обработку на земле с передачей результатов по Wi-Fi.

# Обучение модели YOLO11


## Требования

|  Компонент |  Минимум |  Рекомендуется |
|  Python |  3.8+ |  3.10+ |
|  ОЗУ |  8 ГБ |  16 ГБ |
|  GPU (графический процессор) |  Не требуется (медленно) |  NVIDIA с 4+ ГБ VRAM (памяти видеокарты) |
|  Диск |  5 ГБ |  20 ГБ |


Если GPU нет — используйте **Google Colab** (бесплатный GPU T4 по несколько часов в день). Обучение на CPU занимает в 10—50 раз дольше.


## Установка


```
pip install ultralytics

```


Библиотека `ultralytics` — официальный пакет для работы с YOLOv8 и YOLO11. Содержит инструменты для обучения, валидации и инференса.


## Структура data.yaml


Пример для задачи с двумя классами:


```
path: /home/user/dataset  # абсолютный путь к датасету
train: images/train
val: images/val
nc: 2
names:
- 'red_cube'
- 'blue_cube'

```


При обучении в Google Colab используйте путь вида `/content/dataset`.


## Обучение YOLO11n


```
from ultralytics import YOLO

# Загрузить предобученную модель (скачается автоматически при первом запуске)
# yolo11n.pt — nano-версия, наименьшая и быстрейшая
model = YOLO('yolo11n.pt')

# Запустить обучение
results = model.train(
    data='data.yaml',  # путь к конфигурации датасета
    epochs=100,        # количество эпох обучения
    imgsz=640,         # размер входного изображения (пиксели)
    batch=16,          # количество изображений в одном батче
    device='cuda'      # 'cuda' для GPU, 'cpu' для процессора
)

```


Результаты сохраняются в папку `runs/detect/train/` — там находятся веса модели, графики и метрики.


## Параметры обучения

|  Параметр |  Типичные значения |  Рекомендация для Микродрона |
|  `epochs` |  50—300 |  100—150 для небольшого датасета |
|  `imgsz` |  320, 416, 640 |  640 — стандарт, 320 — если мало данных |
|  `batch` |  8, 16, 32 |  16 для GPU 4 ГБ; 8 если не хватает памяти |
|  `device` |  `'cuda'`, `'cpu'`, `'mps'` |  `'cuda'` на GPU, `'cpu'` на Colab без GPU |
|  `lr0` |  0.001—0.01 |  Оставьте по умолчанию |
|  `patience` |  50 |  Остановить, если нет улучшений N эпох |


### Добавить раннюю остановку


Чтобы не тратить время на обучение после достижения максимума качества:


```
results = model.train(
    data='data.yaml',
    epochs=200,
    imgsz=640,
    batch=16,
    device='cuda',
    patience=30  # остановить, если mAP50 не улучшается 30 эпох подряд
)

```


## Мониторинг обучения


В процессе обучения YOLO выводит метрики после каждой эпохи. Ключевые показатели:


### Loss (потери)

|  Метрика |  Что означает |  Хороший признак |
|  `box_loss` |  Ошибка предсказания bbox |  Уменьшается к концу обучения |
|  `cls_loss` |  Ошибка классификации |  Уменьшается |
|  `dfl_loss` |  Ошибка распределения |  Уменьшается |


Если loss перестал уменьшаться — обучение достигло предела с текущим датасетом.


### mAP (mean Average Precision)

|  Метрика |  Что означает |  Ориентиры |
|  `mAP50` |  Точность при IoU ≥ 0.5 |  > 0.7 — хорошо; > 0.9 — отлично |
|  `mAP50-95` |  Точность при разных порогах IoU |  > 0.5 — хорошо |


**IoU** (Intersection over Union) — степень перекрытия предсказанного bbox с реальным. При IoU ≥ 0.5 обнаружение считается верным.


### Когда остановить обучение

- Loss на validation перестал уменьшаться или начал расти — признак переобучения.
- mAP50 вышел на плато и не растёт несколько эпох.
- Используйте `patience` для автоматической ранней остановки.

Графики метрик доступны в `runs/detect/train/results.png` — рекомендуется проверять после обучения.


## Экспорт модели


После обучения основной файл весов — `runs/detect/train/weights/best.pt`. С ним можно работать на компьютере напрямую или экспортировать в ONNX, чтобы проверить инференс на другой платформе:


```
from ultralytics import YOLO

model = YOLO('runs/detect/train/weights/best.pt')

# Экспорт в ONNX

# Создаст файл runs/detect/train/weights/best.onnx

```

>

**Внимание** Этого ONNX-файла недостаточно для запуска на бортовом компьютере Микродрона — плата работает только с форматом `.cvimodel`. Подготовка модели для дрона описана ниже в разделе «Перенос модели на Микродрон».


## Тест инференса


Проверьте модель на тестовом изображении перед переносом на Микродрон:


```
from ultralytics import YOLO

model = YOLO('runs/detect/train/weights/best.pt')

# Инференс на одном изображении
results = model.predict('test_image.jpg', conf=0.5)

# Вывод результатов
for result in results:
    for box in result.boxes:
        cls_id = int(box.cls)
        confidence = float(box.conf)
        x1, y1, x2, y2 = box.xyxy[0].tolist()
        print(f"Класс: {result.names[cls_id]}, уверенность: {confidence:.2f}")

```


## Типичные проблемы


### Переобучение (overfitting)


**Признак:** loss на обучающей выборке продолжает падать, а на validation — растёт или стоит на месте.


**Решения:**

- Увеличить датасет — добавить разнообразные изображения.
- Включить аугментацию: `augment=True` в параметрах обучения (включена по умолчанию).
- Уменьшить количество эпох или использовать `patience`.
- Использовать более лёгкую модель (YOLO11n вместо YOLO11s).

### Модель не обнаруживает объекты


**Признак:** на тестовых изображениях объекты не обнаружены или уверенность очень низкая (< 0.3).


**Решения:**

- Проверить разметку — открыть несколько txt-файлов и убедиться, что координаты корректны.
- Добавить данные — возможно, 200 изображений недостаточно для этого объекта.
- Снизить порог уверенности при инференсе: `model.predict(..., conf=0.25)`.
- Проверить `data.yaml` — убедиться, что пути и названия классов верны.

### Низкий mAP (< 0.5)


**Решения:**

- Проверить баланс классов — возможно, один класс сильно доминирует.
- Увеличить разнообразие данных.
- Проверить разметку — распространённая причина низкого mAP — неточные или ошибочные bbox.
- Попробовать большую модель (YOLO11s), если ресурсы позволяют.

### Ошибка нехватки памяти GPU (CUDA out of memory)


**Решение:** уменьшить batch: `batch=8` или `batch=4`. Или уменьшить `imgsz=416`.


## Перенос модели на Микродрон


Бортовой компьютер Микродрона имеет аппаратный NPU (нейросетевой ускоритель), который работает с форматом `.cvimodel`. Обученную модель нужно конвертировать из PyTorch в `.cvimodel` — это можно сделать самостоятельно.


Готовый пример — Google Colab-ноутбук [yolo_train_and_export.ipynb](https://git.sverk.io/tiny_control/edu/ml/-/blob/master/yolo_train_and_export.ipynb): он обучает модель и сразу экспортирует её в `.cvimodel`.


>

**Подсказка** Ноутбук покрывает весь цикл — от обучения до экспорта в `.cvimodel`, поэтому им удобно пользоваться целиком, без ручного запуска обучения из предыдущих разделов.


### Как устроена конвертация


Конвертация идёт в несколько этапов — все они выполняются ноутбуком автоматически:

- Экспорт обученной модели `.pt` в формат ONNX (вход 640×640).
- Преобразование ONNX в промежуточный формат `.mlir` с нормализацией изображения.
- Калибровка на ~200 изображениях из обучающей выборки — нужна для квантизации в int8.
- Сборка итогового `.cvimodel` под процессор `cv181x` бортового компьютера.

Для конвертации используется тулкит Sophgo tpu-mlir. Готовые команды каждого этапа уже прописаны в ноутбуке — менять их обычно не нужно.


>

**Примечание** Калибровочные изображения должны быть из того же набора, на котором обучалась модель, иначе точность после квантизации в int8 заметно упадёт.


### Шаг 1. Скопировать модель на дрон


Скопируйте готовый файл `.cvimodel` на бортовой компьютер:


```
scp your_model.cvimodel root@10.10.1.1:/root/

```


Или, если работаете по Wi-Fi после подключения к роутеру, укажите IP-адрес дрона в сети.


### Шаг 2. Запустить детектор


Детектор запускается командой на борту дрона:


```
/root/packages/yolo_detector your_model.cvimodel 3 0.3 0.3 1 1

```


Параметры команды:

- `your_model.cvimodel` — путь к файлу модели
- `3` — ID класса для обнаружения (зависит от вашей модели: 0 = первый класс, 1 = второй, и т.д.)
- `0.3` — порог уверенности объекта (`obj_thresh`): объекты с `score < 0.3` игнорируются
- `0.3` — порог NMS (non-maximum suppression): фильтрация перекрывающихся обнаружений
- `1 1` — дополнительные параметры (стриминг и публикация в ROS-топик)

>

**Подсказка** Подбирайте `obj_thresh` экспериментально. Значение 0.3 — хорошая стартовая точка. Если много ложных срабатываний — увеличьте до 0.5—0.7. Если объект плохо обнаруживается — уменьшите до 0.2.


### Шаг 3. Проверить стрим с обнаруженными объектами


На компьютере можно посмотреть видеопоток с отрисованными bbox:


```
ffplay -fflags nobuffer -flags low_delay -rtsp_transport udp rtsp://10.10.1.1:8554/stream

```


### Шаг 4. Получение обнаруженных объектов в Python-скрипте


После запуска `yolo_detector` результаты доступны через стандартный API:


```
from simple_offboard_py import SimpleOffboard

drone = SimpleOffboard()

# Детектор уже запущен на борту — просто читаем результаты
for det in drone.get_detections():
    print(f"{det.label} (score={det.score:.2f}) bbox=({det.x1},{det.y1})-({det.x2},{det.y2})")

```


Убедитесь, что модель работает корректно: запустите детектор при нескольких положениях объекта и проверьте, что результаты обнаружения стабильны. Если точность заметно хуже, чем при тестировании на компьютере, вероятно, условия съёмки (освещение, высота, угол) в датасете отличались от реальных — дособерите данные.

# Аккумуляторы


## 1. Основные характеристики и маркировка


Прежде чем приступать к работе, разберите маркировку аккумулятора (АКБ) — от неё зависят режим и параметры зарядки.


Рассмотрим на примере АКБ **GNB 850mAh 1S1P 4.35V LiHV**, которым комплектуется Микродрон:


![](https://api.edu.sverk.tech/api/courses/import/gitlab/asset?origin=https%3A%2F%2Fgit.sverk.io&project=SES%2Fdocs&ref=main&path=whoop%2Fassets%2Fkb-battery%2Fbattery.png&sig=47c0e053f548121bec69a90eb1c166e03b0ade14c0bcfec272163b3bff90f0c5)


- **1S (Serial)** — количество ячеек (банок), соединённых последовательно. Здесь одна ячейка, поэтому номинальное напряжение АКБ равно напряжению одной банки.
- **1P (Parallel)** — количество ячеек, соединённых параллельно. Здесь одна ячейка без параллельной сборки, отдельный балансировочный разъём не требуется.
- **850 mAh** — ёмкость аккумулятора.
- **LiHV 4.35V** — литий-полимерный аккумулятор повышенного напряжения; максимальное напряжение зарядки — 4.35 V.
- **60C/120C** — допустимая токоотдача под нагрузкой.

>

**Примечание** С Микродроном могут использоваться и 2S-аккумуляторы. В этом случае нужно применять другое зарядное устройство (ЗУ) с поддержкой 2S и балансировкой по ячейкам.


## 2. Напряжение ячеек


Эти значения важны для выбора типа АКБ и контроля допустимого диапазона напряжений.

|  Тип АКБ |  Восстановление |  Минимум |  Номинал |  Хранение |  Максимум |
|  LiIon |  2.8V |  3.3V |  3.6V |  3.7V |  4.1V |
|  LiPo |  2.6V |  3.4V |  3.7V |  3.8V |  4.2V |
|  LiHV |  2.6V |  3.55V |  3.85V |  3.95V |  4.35V |

- **Восстановление** — напряжение, при снижении до которого стандартная зарядка может не запускаться.
- **Минимум** — минимальное рекомендуемое напряжение разряда.
- **Номинал** — напряжение, используемое для маркировки и расчёта характеристик АКБ.
- **Хранение** — рекомендуемое напряжение для длительного хранения.
- **Максимум** — максимально допустимое напряжение зарядки.

## 5. Одновременная зарядка нескольких АКБ


WooPower W63 позволяет одновременно заряжать до 6 отдельных 1S-аккумуляторов — каждый порт работает независимо.


При одновременной зарядке убедитесь, что все подключённые аккумуляторы относятся к одному поддерживаемому типу 1S и для них выбраны корректные параметры режима, конечного напряжения и тока.


## 6. Техника безопасности и хранение

- Не оставляйте аккумуляторы на зарядке без присмотра.
- Не используйте повреждённые, вздутые или перегретые аккумуляторы.
- Не допускайте короткого замыкания контактов аккумулятора.
- Не заряжайте аккумулятор сразу после полёта — дайте ему остыть.
- Для длительного хранения используйте режим **Storage**.
- Храните аккумуляторы в сухом месте при умеренной температуре, вдали от источников тепла и прямого солнечного света.

>

**Внимание** В случае возгорания литиевого аккумулятора не тушите его водой — используйте песок или порошковый огнетушитель.

# Оптический поток


Микродрон удерживает положение в пространстве без спутниковой навигации — за это отвечает **датчик оптического потока**. Понимание того, как он работает, помогает добиться стабильного полёта, особенно в автономном режиме.


## Зачем нужен оптический поток


Спутниковая навигация GPS (Global Positioning System) в помещении недоступна или слишком неточна. Поэтому микродрон определяет своё горизонтальное смещение по картинке с направленной вниз камеры — этот метод и называется оптическим потоком.


>

**Примечание** В [предполётной проверке](/learn/whoop/check) пункт **gps** имеет статус FAIL — это норма. За положение отвечает оптическая навигация (пункт **vision position**).


## Как это работает

- Направленная вниз камера снимает поверхность под микродроном.
- Система сравнивает соседние кадры и вычисляет, насколько и в какую сторону сместился рисунок поверхности.
- По этому смещению определяется горизонтальная скорость и положение микродрона.
- Высота над поверхностью измеряется отдельным направленным вниз датчиком — без неё нельзя правильно пересчитать смещение кадра в метры.

Результат этих вычислений микродрон отдаёт как одометрию — те самые координаты, которые возвращает метод [`get_position()`](/learn/whoop/autonomous) и которые удерживает [режим POSITION](/learn/whoop/manual-flight-position).


## Требования к поверхности и условиям


Оптический поток работает по рисунку поверхности, поэтому ему нужна **видимая текстура и хорошее освещение**:

|  Хорошо |  Плохо |
|  Текстурированный пол (рисунок, ковёр, разметка) |  Однотонная, гладкая поверхность |
|  Равномерное хорошее освещение |  Темнота, резкие тени, мерцание света |
|  Матовая поверхность |  Зеркальные и бликующие поверхности (стекло, лужи) |


>

**Подсказка** Если автономный полёт нестабилен — в первую очередь проверьте поверхность и освещение под микродроном.


## Настройка


Отдельная ручная настройка оптического потока не требуется — он включается базовым набором параметров полётного контроллера (см. «[Загрузка параметров](/learn/whoop/setup-params)»). После загрузки параметров оптическая навигация активна.


В отличие от [гироскопа и акселерометра](/learn/whoop/setup-calibration), датчик оптического потока не требует отдельной калибровки в QGroundControl. Достаточно убедиться, что он работает.


## Как проверить, что оптический поток работает

- Выполните [предполётную проверку](/learn/whoop/check) — пункт **vision position** должен быть пройден.
- Взлетите в [режиме POSITION](/learn/whoop/manual-flight-position) и отпустите стики. При исправном оптическом потоке микродрон зависает на месте и не уплывает.
- В программе выведите координаты через `get_position()` — у неподвижного микродрона они должны оставаться примерно постоянными.

## Частые проблемы

|  Признак |  Вероятная причина |
|  Микродрон медленно уплывает в сторону |  Слишком однотонная или плохо освещённая поверхность |
|  Положение «прыгает», координаты скачут |  Блики, мерцание света или повторяющийся рисунок поверхности |
|  Потеря позиции на высоте |  Слишком большая высота — поверхность теряет детализацию |


>

**Внимание** В автономном полёте удержание позиции полностью зависит от оптического потока. Запускайте автономные программы над текстурированной, хорошо освещённой поверхностью.
