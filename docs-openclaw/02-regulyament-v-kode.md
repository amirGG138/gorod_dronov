# Регламент, переписанный в код

Самая полезная часть репозитория. Источники:
`snapshot/agent/roles/city_world.py` (409 строк), `city_executor.py` (236),
`city_missions.py` (460), `snapshot/test_fixtures/city-1/map.json`,
`snapshot/tests/test_city.py`, `test_city_agents.py`, `test_city_e2e.py`.

Ключевая идея разделения: **LLM предлагает и объясняет, детерминированное ядро
планирует, проверяет и исполняет.** Ни один план от модели не доходит до робота,
минуя компилятор и валидаторы. Это же ядро — оракул для тестов: полная
15-минутная попытка прогоняется в симулированном времени за миллисекунды.

## Энергия ровера

```python
class EnergyLedger:
    """старт 0; +1 за каждую ПОДТВЕРЖДЁННУЮ секунду стоянки в зоне зарядки;
       −1 за переход в соседнюю клетку; движение блокируется при 0."""
    def charge(self, seconds):  # засчитываются только целые подтверждённые секунды
    def spend_move(self):       # при energy <= 0 бросает EnergyError
```

Диспетчер **предзаряжает ровер на весь план сразу**, а не по ходу:

```python
budget = plan_total_energy(world, order) + 2   # +2 резерв
rover.charge(budget)
```

`plan_total_energy` считает переходы всего упорядоченного плана **включая
возврат в зону зарядки между миссиями** — правило резерва: ровер не должен
остаться с нулём вдали от зарядки. Для боевого прогона бюджет считается точнее:
`compile_rover_plan` прогоняет A* по каждому участку `navigate` и берёт
`moves + 4`.

## Валидаторы стоянок

```python
WATER_DWELL_S = 3.0     # башня: стоянка не менее 3 секунд
LOAD_DWELL_S  = 5.0     # доставка: погрузка 5 секунд
ESCORT_MAX_LAG = 2      # эскорт: отставание не более 2 клеток
MAX_ALT_M = 4.0         # потолок полёта

def water_dwell_valid(seconds, *, moved=False, in_zone=True, led_on=True):
    return (not moved) and in_zone and led_on and seconds >= WATER_DWELL_S
```

Проверяется четыре условия сразу: не двигался, в нужной клетке, лента включена,
секунд достаточно. **2,9 с не засчитываются**, движение во время стоянки — не
засчитывается, выключенная лента — не засчитывается. Негативные тесты на это
есть (`tests/test_city.py`).

## Маршрут «Пожар»

`fire_route(world) -> (actions, moves)`. Уровень N = **ровно N подтверждённых
циклов** «башня → 3 с стоянки с мигалкой → подъезд к пожару → тушение».

Важная деталь: пожар горит **в доме**, то есть в клетке-здании, куда роверу
въезжать нельзя. `fire_approach()` выбирает клетку-дорогу, соседнюю с горящим
домом, **ближайшую к водонапорной башне** — так короче циклы. Ровер никогда не
входит в клетку пожара.

Ёмкость бака `WATER_CAPACITY = 1` (регламент: одна единица воды за поездку),
вынесена в переменную окружения — если окажется, что везти можно больше,
меняется одним значением и число поездок падает.

Скомпилированные действия атомарны и несут доказательства:

```python
Action("fire-1-water-dwell", "dwell", cell=tower, seconds=3.0, led="blink",
       preconditions=["in_water_zone", "speed_zero"],
       success_evidence=["pose_stable_3s", "led_on_3s", "water_loaded_1"],
       timeout=8)
```

## Маршрут «Доставка»

`delivery_route(world, avoid_fire=True)`: зарядка → погрузка (5 с стоянки с
мигалкой) → запуск эскорта и маячка → финиш.

Пока пожар не потушен, клетка пожара передаётся в A* как заблокированная; если
это убивает все маршруты — бросается `RouteBlocked` с текстом «маршрут доставки
заблокирован непотушенным пожаром». Это не ошибка, а сигнал планировщику
поменять порядок миссий.

Эскорт (`SimSafetyDrone.escort_step`) идёт строго **сзади**: встаёт на
**предыдущую** клетку ровера, отставание считается как манхэттенское расстояние,
превышение 2 клеток пишет событие `ESCORT_VIOLATION`.

## Планировщик порядка миссий

```python
score = danger * 10 - energy_cost        # прозрачная, объяснимая формула
```

Плюс **жёсткое ограничение-предшественник**: если маршрут доставки не проходит
мимо непотушенного пожара, `fire` принудительно ставится первым, а в причинах
пишется человекочитаемое «доставка не проходит мимо пожара — сначала тушим».
Именно это объяснение потом попадает в сообщение координатора и в логи — то, за
что регламент даёт баллы за «принятие решений агентами».

## Формат логов доказательств

Каждое действие завершается событием с доказательствами:

```jsonc
{"type": "ACTION_COMPLETED", "action_id": "fire-1-water", "agent_id": "rover",
 "evidence": {"cell": [1,3], "stationary_seconds": 3.0, "led": true,
              "counted": true, "water_loaded": 1}}
```

Другие типы: `MISSION_ORDER` (с причинами), `CHARGED`, `FIRE_EXTINGUISHED`,
`ESCORT_LAUNCHED`, `DELIVERY_DONE`, `PERSON_FOUND`, `SAFETY_VIOLATION`,
`ESCORT_VIOLATION`, `ENERGY_BLOCK`, `REPLAN_NEEDED`, `ROVER_DONE`,
`ACTION_ERROR`. Всё уходит в `events.jsonl` и на дашборд `/city`.

Журнал воспроизводим: судья может прогнать его заново и получить тот же
результат. Это сильный аргумент на техзащите, и он стоит дёшево — просто пишите
события с самого начала, а не прикручивайте логи в конце.

## Роли в сценарии города

`agent/roles/city_missions.py`, фазы `INIT → SURVEY → EXECUTE → DONE`:

- **координатор** — строит `WorldModel` 6×6 из карты, режет поле на зоны
  разведки, ждёт облёта, сводит наблюдения, ранжирует миссии, компилирует план
  ровера, ждёт исполнения, публикует итог;
- **разведчики** — сначала публикуют `CLAIM` (какие клетки беру — видимая
  координация), потом летят, снимают, гоняют VLM, публикуют `OBSERVATION` со
  структурированными детекциями;
- **ровер** — исполняет скомпилированный план через бридж: заряд, поклеточная
  езда, стоянки с лентой, события-доказательства;
- **ВУП (`safety_drone`)** — в SURVEY ищет человека в окне у пожара, в EXECUTE
  сопровождает ровер.

Сведение фактов — голосованием: `_confirmed(kind, min_votes)` берёт клетку с
большинством детекций, а **уровень пожара — медиану** чисел, считанных с
маркера разными дронами. Параметр `min_votes=2` требует независимого
подтверждения (регламентные «спорные факты»); по умолчанию стоит 1.

Разбиение на зоны — два режима: смежные квадранты (оптимальные траектории) и
`SURVEY_ROUNDROBIN=1` — каждый дрон берёт по 2 клетки по кругу змейкой. Второй
хуже по пути, но зрелищнее: всё поле подметается четырьмя дронами одновременно.
Мелочь, но на демонстрации она работает.
