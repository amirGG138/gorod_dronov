# OpenClaw Stack — рой дронов, который сам договаривается и сам платит

Четыре дрона и ровер получают задачу, **в открытом чате делят поле между
собой**, облетают его, перепроверяют находки друг за другом и доводят ровер до
цели. Параллельно они **расплачиваются друг с другом на блокчейне** за зарядку,
воду и разведку — по протоколам x402 и AP2, с полноценной цепочкой мандатов и
квитанций.

Всё это крутится в Docker **без единого дрона на столе**. Тот же код без
изменений уезжает на реальные борта с Raspberry Pi.

Это README для людей. Если вы агент — вам в [AGENTS.md](AGENTS.md).

---

## Быстрый старт

Нужен только Docker. Ключи и железо не обязательны.

```bash
make demo-survey        # миссия: 4 дрона делят поле 5×5, ищут груз, ровер едет
# открыть http://localhost:8095/survey

make payments-demo      # экономика: 7 сделок на локальном блокчейне
# открыть http://localhost:8090

make demo-survey-commerce   # то и другое сразу, на одном дашборде
```

Остановить: `make down`. Начать с чистого листа: `make reset`.

По умолчанию мозг агентов — детерминированный мок: демо воспроизводимо и не
требует ключей. Как включить настоящую LLM — ниже.

## Что здесь есть

### Миссия

| Сценарий | Команда | Что происходит |
|---|---|---|
| Поиск груза | `make demo-survey` | Дроны делят поле 5×5 в чате, летают по плану, перепроверяют находку по очереди, ровер едет к подтверждённому грузу |
| Умный ровер | `make demo` | Дроны фотографируют улицу, сертифицируют проезд, ровер едет A → B |
| Город дронов | `make demo-city` | Пожар, доставка, энергия, дрон безопасности |
| Художники | `make demo-painters` | Четыре художника с разными характерами договариваются о сюжете и пишут общую картину |
| Дебаты | `make demo-studio` | Пошаговый движок дебатов с модератором |

### Экономика

Агенты — не метафора «сервисов», а реальные плательщики. Дрон покупает зарядку
у станции, воду у водокачки, разведку у другого дрона. Каждая сделка проходит
путь `котировка → торг → мандат AP2 → HTTP 402 → расчёт → квитанция` и ложится
на блокчейн.

| Что | Команда |
|---|---|
| Демо на локальном anvil | `make payments-demo` |
| Тесты платежей | `make payments-test` |
| На TON (testnet) | `make payments-ton-demo` |

Токен демо-экономики — **SVERK** (6 знаков после запятой).

### Дашборды

| Адрес | Что показывает |
|---|---|
| `:8095/survey` | Поле, дроны, покрытие, живые мысли агентов |
| `:8095/survey-commerce` | То же + платежи поверх миссии |
| `:8090` | Блок-эксплорер: сделки, участники, балансы, аудит каждой сделки |
| `:8081/docs` | API коммерции (OpenAPI) |

> Порт **8095**, а не 8080: на машинах разработки 8080 обычно занят контейнером
> симулятора. Переопределяется через `VIZ_HOST_PORT`.

## Хакатон: один ноутбук раздаёт всё

Один хост поднимает блокчейн и оба дашборда, остальные подключаются по wifi.

```bash
make demo-hackathon
```

Печатает готовые ссылки:

```
publishing on wlo1 (192.168.1.150) — uplink not exposed
mission dashboard: http://192.168.1.150:8095/survey-commerce
crypto dashboard:  http://192.168.1.150:8090
shared RPC:        http://192.168.1.150:8545   chainId 31337
```

Адрес берётся с **wifi-интерфейса**, а не с маршрута по умолчанию: интернет
обычно приходит по проводу, и адрес провода участникам бесполезен. Если угадало
неверно — `make demo-hackathon LAN_IFACE=wlan0` или `LAN_IP=…`.

Ноду anvil запускается с канонической тестовой мнемоникой и 20 счетами по
10000 ETH, так что участник импортирует знакомый ключ и сразу работает:

```
Network   OpenClaw Hackathon
RPC URL   http://<адрес хоста>:8545
Chain ID  31337
```

### ⚠️ Про безопасность этого режима

Это следует прочитать целиком, а не по диагонали.

RPC открыт без аутентификации и отдаёт наружу `anvil_setBalance` и
`anvil_impersonateAccount`. Любой в этой сети может напечатать себе денег,
выдать себя за чужой адрес или сломать цепочку. Для хакатона это приемлемо —
деньги игрушечные, — но:

* мнемоника `test test … junk` публичная, эти адреса известны всему интернету;
  ничего настоящего на них класть нельзя;
* сервисы слушают **только** wifi-адрес, чтобы неаутентифицированный RPC не
  торчал в интернет-аплинк; проверить можно командой `ss -ltn`;
* если запустить compose-файлы руками без `LAN_BIND_IP`, всё свалится на
  `127.0.0.1` — это сделано намеренно, чтобы ошибка закрывала доступ, а не
  открывала лишнее.

### Повторные прогоны миссии

```bash
make mission-rerun
```

**Не запускайте `make demo-hackathon` повторно, когда участники уже
подключились.** Этот таргет начинается со сноса томов: цепочка откатится на
нулевой блок, токен переразвернётся по новому адресу, а у всех подключившихся
сломаются nonce в кошельках. `mission-rerun` перезапускает только агентов и
блокчейн не трогает.

### Участники: подключиться к общей ноде

Команды берут этот же репозиторий, но **свой блокчейн не поднимают**:

```bash
make payments-client \
  PAYMENTS_RPC_URL=http://192.168.1.150:8545 \
  PAYMENTS_DEPLOYER_PRIVATE_KEY=0x5de4…365a
```

Каждая команда разворачивает **свой токен и своих участников** на общей
цепочке. Так и задумано: общий деплой-ключ на две команды означает гонку по
nonce и перемешанные балансы. Берите разные индексы счетов из мнемоники.

Панели участника слушают только `localhost` — это его личный дашборд.

## Настоящая LLM вместо мока

```bash
cp .env.example .env      # MODEL_PROVIDER=sverk, MODEL=qwen35, SVERK_API_KEY=…
make demo-sverk
```

Поддерживаются `sverk` (шлюз `ai.sverk.tech/v1`, OpenAI-совместимый),
`anthropic`, `openai`, `ollama`.

⚠️ Одна деталь, которая незаметно портит демо: агенты сидят в сети `mesh` с
`internal: true`, то есть **без выхода в интернет**. Без оверлея
`docker-compose.egress.yml` вызов модели не уходит наружу, а агенты молча
переключаются на шаблонные реплики — по дашборду это не отличить от настоящего
прогона. Таргеты `demo-sverk` и `mission-rerun EGRESS=1` этот оверлей
подключают сами.

С реальной моделью каждый ход упирается в `MODEL_TIMEOUT` (по умолчанию 30 с),
так что прогон заметно дольше мока. Перед показом прогоняйте заранее.

## Настоящие дроны по локальной сети

Дроны и роверы не обязаны жить на одной машине. Каждый борт — отдельный узел,
который ходит к хабу по HTTP.

```bash
# на хабе (оркестраторе)
HUB_TOKEN=$(openssl rand -hex 16) make hub

# на каждом борту
HANDLER_ID=team-7 FLEET=city HUB_URL=http://10.0.0.2:8096 HUB_TOKEN=…
docker compose -p drone-3 -f docker-compose.drone.yml --env-file .env.drone up -d
```

Когда в одной сети несколько команд, борта не путаются: у каждого есть
`HANDLER_ID` и `FLEET`, чужой хаб отказывает дрону с внятной причиной (409), а
поверх — общий `HUB_TOKEN` команды. Привязка «этот борт — этого хендлера»
лежит в постоянной памяти и переживает перезагрузку и смену IP.

Первичная привязка — на странице хаба `/fleet`: оператор выбирает цвет, жмёт
«мигнуть», глазами убеждается, что мигает нужный борт, и подтверждает.

Проверить всю сетевую обвязку без железа:

```bash
make demo-distributed     # 4 дрона + ровер как отдельные узлы через HTTP-хаб
```

Подробности: [docs/fleet.md](docs/fleet.md), [docs/distributed.md](docs/distributed.md),
[docs/on-drone.md](docs/on-drone.md).

## Если что-то не работает

**Порт занят.** 8080 почти всегда занят посторонним контейнером. Дашборд —
`VIZ_HOST_PORT`, хаб — `HUB_HOST_PORT` (по умолчанию 8096).

**Конфликт имён контейнеров.** `demo-distributed` и `demo-survey-commerce`
используют одинаковые `container_name` (`coordinator`, `drone-1`, …) и вместе
не поднимутся. Сначала опустите один.

**С самого хоста дашборд не открывается, а с других машин открывается.**
Если поднят VPN (например Mullvad), он режет трафик, у которого источник и
получатель — один и тот же LAN-адрес. На хосте используйте `localhost`.

**Дашборд показывает старые данные после изменения фронта.** Кэш браузера,
жёсткий перезагруз (Ctrl+Shift+R).

Полный разбор: [docs/troubleshooting.md](docs/troubleshooting.md).
