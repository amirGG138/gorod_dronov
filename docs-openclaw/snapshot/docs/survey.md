# Survey — город дронов v2: поиск груза на поле клеток

Четыре дрона-разведчика договариваются, как разделить поле W×H (по умолчанию
5×5), ходами облетают свои зоны, фотографируют каждую клетку сверху и сразу
анализируют снимок. Находку **по очереди** перепроверяют остальные дроны;
кворум подтверждает — и к клетке с грузом выезжает ровер. Ложная тревога
(обманка) отклоняется, и поиск продолжается.

```bash
make local-survey          # локально, mock-мозг (детерминированно, без ключей)
make demo-survey           # docker; MODEL_PROVIDER из .env добавляет egress
# стенд: http://localhost:8080/survey
```

## Фазы

```
INIT ─▶ CHAT ─▶ EXECUTE ─▶ REPORT ─▶ DONE
          ▲         │▲________│  (reopen: не всё покрыто, раунд < SURVEY_MAX_ROUNDS)
          └ SURVEY_CHAT=0 — зоны раздаются по кругу без переговоров
```

| Фаза | Что происходит | Выход |
|---|---|---|
| INIT | Координатор пишет `task.md`, конфиг и стартовый `world.json` (сетка, зоны, старт ровера). | сразу |
| CHAT | Дроны в открытом канале делят зоны Z1..Zn (`survey_scout.survey_chat_turn`): заявка → спор → обмен, `done`-консенсус. Механика та же, что у скаутов города и мастерской. | done-консенсус **или** дедлайн |
| EXECUTE | Ходы облёта + верификация находок (ниже). Дедлайн — сторожевой: пока у дронов свежий прогресс, координатор продлевает его. | груз подтверждён / поле покрыто / глухой дедлайн |
| REPORT | Если груз подтверждён — ждём ровер и выносим вердикт; если покрытие неполное — один повторный раунд EXECUTE; иначе `FAIL`. | ровер приехал / вердикт записан |

## Ход дрона — «джейсонка»

Каждый ход дрон публикует **JSON-план действий**, который исполняет
автопилот (bridge). Формат — ровно тот, что в ТЗ:

```json
{
  "thinking": "клетки [3,2] и [4,2] ближайшие непройденные…",
  "say": "иду по нижнему ряду",
  "actions": [
    {"do": "fly_to", "cell": [1, 1]},
    {"do": "wait",   "seconds": 20},
    {"do": "photo_analyze"}
  ]
}
```

* `fly_to` — перелёт в клетку; **можно через несколько клеток за раз** (маршрут
  строит бридж/автопилот). За один ход разрешено до `SURVEY_CELLS_PER_TURN`
  связок fly→wait→photo (по умолчанию 2).
* `wait` — модель времени долёта («подождать 20 сек, чтобы дрон долетел»);
  планировщик масштабирует её на дистанцию (`SURVEY_WAIT_SEC` × клетки, потолок
  `SURVEY_WAIT_MAX`). В симуляции ожидания сжимаются `WAIT_SCALE` (демо: 0.05 →
  20 с ≈ 1 с; на железе ставьте 1.0).
* `photo_analyze` — фото ТЕКУЩЕЙ клетки сверху + мгновенный анализ
  (`/photograph {cell}` + `/analyze {cell}` бриджа). `close_look: true` —
  снижение для перепроверки находки.

План строит LLM (JSON по схеме, sampler-enforced на sverk); mock-мозг и любой
сбой LLM дают детерминированный план «следующие клетки зоны змейкой»
(`survey_common.sweep_plan`) — протокол не зависает никогда. Валидатор
(`validate_plan`) вырезает чужие глаголы, клампит клетки в поле и в СВОЮ зону,
режет ожидания — сырой вывод модели не управляет дроном напрямую.

Исполненный план уходит на доску сообщением `PLAN` (payload: `plan`, `results`,
`pose`) — это и есть «выход каждого хода».

## Closed loop (позиция дрона)

После каждого `fly_to` дрон опрашивает бридж `GET /pose` и работает с той
клеткой, где он **реально** оказался: фото привязывается к позе, поза уходит в
`progress` → координатор собирает `world.positions`. На mock-бридже поза всегда
совпадает с командой; на железе (`bridge/ros2/bridge_node.py`) это реальная
телеметрия ROS2 — дрейф виден сразу, дрон делает одну повторную попытку и
продолжает с фактического места. Никакого «я, наверное, там, куда летел».

## Верификация находки — «все по очереди»

1. Анализ клетки сказал «груз» → дрон вещает `FOUND {cell, confidence}` всем.
2. Координатор открывает кандидата: `world.mode = verify`, очередь — все
   остальные дроны. **По одному**: очередному приходит `ASSIGNMENT
   {verify_cell}`, он летит, снижается (`close_look`), голосует `VERIFY {cell,
   cargo: true/false}`. Пока очередь не его, дрон продолжает осмотр своей зоны.
3. Правило (`survey_common.quorum_state`): подтверждено при `VERIFY_QUORUM`
   голосах «да» (по умолчанию 2 из 3). `VERIFY_ALL=1` (по умолчанию) — ждём
   всех проверяющих; `VERIFY_ALL=0` — решаем, как только исход математически
   ясен. Проверяющий, молчащий дольше `VERIFY_LEG_SEC`, **пропускается**
   (мёртвый дрон не замораживает миссию), но пропуск обратим: опоздавший
   `VERIFY` всё равно засчитывается — медленный LLM-ход не выбрасывает
   настоящий вердикт (поймано в первом живом прогоне на sverk).
4. **Подтверждено** → `world.goal = клетка`, `world.ready = true` — ровер
   (обычная роль rover, без изменений) едет и докладывает. **Отклонено** →
   клетка помечается `rejected`, координатор объявляет «ложная тревога —
   продолжаем осмотр», и поиск идёт дальше. Несколько находок встают в очередь
   и проверяются последовательно.

Фикстура `test_fixtures/survey-1` разыгрывает оба пути: обманка в `[2,1]`
(с высоты похожа на груз, вблизи — мусор) отклоняется 0/3, настоящий груз в
`[1,3]` подтверждается 3/3.

## Устойчивость

* **Зоны и кража клеток**: клетки живого соседа неприкосновенны; если хозяин
  зоны не обновлял `progress` дольше `SURVEY_STALE_SEC` (умер/завис), его
  непройденные клетки может добрать любой освободившийся дрон.
* **Дедлайн EXECUTE — сторож, а не бюджет**: рассчитывается от объёма работ
  (клетки × время долёта / дроны) и продлевается, пока есть свежий прогресс.
* **«Груз не найден»** объявляется только когда поле покрыто, нет активного
  кандидата, нет непроверенных `FOUND` и все дроны отчитались `zone_done` —
  это закрывает гонку «находка ещё летит на доску, а покрытие уже полное»
  (поймана в первом живом прогоне).

## Сообщения (дополнение к protocol.md)

| type | phase | смысл |
|---|---|---|
| `PLAN` | EXECUTE | исполненный JSON-план хода: `{plan, results, pose}` |
| `FOUND` | EXECUTE | кандидат на груз: `{cell, confidence, label}` |
| `VERIFY` | EXECUTE | вердикт проверяющего: `{cell, cargo, confidence}` |

`world.json` (survey): `grid_size`, `grid` (для A* ровера), `start`, `goal`,
`zones`, `cells{"x,y": {status: covered|candidate|rejected|confirmed}}`,
`positions`, `mode (sweep|verify|done)`, `candidate {cell, by, queue, votes}`,
`confirmed`, `rejected[]`, `ready`, `covered_count`, `total_cells`.

## Конфиг (env)

| Переменная | Умолчание | Что делает |
|---|---|---|
| `SURVEY_CHAT` | `1` | Переговоры о зонах в чате; `0` — раздать по кругу |
| `SURVEY_CELLS_PER_TURN` | `2` | Клеток за один ход |
| `SURVEY_WAIT_SEC` | `20` | Секунд долёта на клетку (та самая «подождать 20 сек») |
| `SURVEY_WAIT_MAX` | `60` | Потолок ожидания за действие |
| `WAIT_SCALE` | `1.0` | Масштаб ожиданий (симуляция: 0.05) |
| `VERIFY_QUORUM` | `2` | Голосов «да» для подтверждения |
| `VERIFY_ALL` | `1` | Ждать всех проверяющих (все летят по очереди) |
| `VERIFY_LEG_SEC` | `240` | Таймаут одного проверяющего (пропуск обратим) |
| `SURVEY_STEAL` | `1` | Добирать клетки умершего соседа |
| `SURVEY_STALE_SEC` | `240` | Порог «хозяин зоны завис» (должен переживать медленный LLM-ход) |
| `SURVEY_MAX_ROUNDS` | `2` | Раундов EXECUTE (reopen пропусков) |

Поле другого размера — свой `map.json` (`grid_size`, `cargo`, `decoys`,
опционально `zones`; без `zones` поле нарежется змейкой автоматически на
любое число дронов).

## Пауза (замена аккумуляторов)

В любой момент: кнопка «⏸ Пауза» на `:8080/survey` или `make pause` — все
дроны садятся, доска замирает, дедлайны сдвигаются; `make resume` — взлёт и
продолжение с РЕАЛЬНОЙ позиции из бриджа (борт можно переставлять). Прерванная
верификация доводится. Подробности: [pause](pause.md).

## PicoClaw / ROS2

Дроны общаются только через blackboard (§1) — на железе через hub
(`HttpBoard`), как и остальные задачи. Мозг дрона может быть нативным PicoClaw:
MCP-шима `drone/picoclaw_bridge_mcp.py` даёт ему те же четыре действия
(`fly_to`≈`move`, `photograph`, `analyze`, `get_pose`) поверх того же
bridge-контракта. Реальный полёт = замена mock-бриджа на `rclpy`-узел с теми же
HTTP-эндпоинтами; протокол, чат и верификация не меняются.
