# Флот: хендлеры, привязка дронов, LED-регистрация

Несколько команд летают в одной локальной сети. Чтобы команды не путались,
чей это дрон:

* у каждого **хендлера** (центрального хаба команды) есть `HANDLER_ID`
  (например `team-7`) и **флот** `FLEET` = `city` | `painter` (по умолчанию
  выводится из задачи: painting → painter, survey/safe_passage → city);
* каждый дрон несёт свой `handler_id` + `fleet` в регистрации и **чужой хаб
  отказывает ему с внятной причиной (409)** — дрон другой команды или другого
  флота не попадёт ни в ростер задач, ни на дашборды;
* поверх этого — общий `HUB_TOKEN` команды: без него хаб вообще не принимает
  записи.

## Унифицированный образ дрона

Один образ (`openclaw-drone` + bridge) ставится на любой борт;
всё различие — **env-профиль проекта**, записываемый одинаковым на все дроны
команды (`.env.drone.example`):

```bash
HANDLER_ID=team-7  FLEET=city  HUB_URL=http://10.0.0.2:8080  HUB_TOKEN=…
docker compose -p drone-3 -f docker-compose.drone.yml --env-file .env.drone up -d
```

`FLEET` переключает и **режим bridge-ноды** (`BRIDGE_MODE=city|painter` — одна
нода, два набора действий, см. [bridge](bridge.md)), и категорию на дашбордах.
Статические IP нужны только хабу: дрон сам ходит к `HUB_URL`, его собственный
адрес никого не волнует.

## Привязка в постоянную память (переживает перезагрузку)

Привязка «этот борт — этого хендлера» хранится на несъёмной памяти Raspberry:
`BIND_FILE=/data/binding.json` (volume `openclaw-binding` в
`docker-compose.drone.yml`):

```json
{"handler_id": "team-7", "hub_url": "http://10.0.0.2:8080",
 "agent_id": "drone-3", "fleet": "city", "bound": true}
```

После перезагрузки дрон стартует **без** `AGENT_ID`/`HANDLER_ID` в env — всё
берётся из привязки (env всегда может переопределить; смена `HANDLER_ID` в env
инвалидирует старую привязку — дрон честно идёт на перерегистрацию). Логика —
`agent/binding.py`, покрыта тестами.

## LED-регистрация («ткнул — мигнул — привязал»)

Фолбэк/основной способ сопоставить физический борт с id — страница хаба
**`:8080/fleet`**:

1. Дрон с профилем проекта поднимается и регистрируется как «не привязан»
   (кандидат).
2. Оператор выбирает цвет и жмёт **«💡 мигнуть»** → хаб кладёт на доску
   `COMMAND {led:{effect:"blink", color}}` для этого id → агент дрона
   исполняет его на своём бридже (`/led` → `drone.led.set_effect(...)` в
   sverk-ros2, эффекты fill/blink/…); карточка на странице мигает тем же
   цветом (событие `led` — живое эхо с борта).
3. Оператор глазами убеждается, что мигает нужный борт, и жмёт
   **«✓ привязать»** → хаб помечает регистрацию bound и шлёт
   `COMMAND {bind:{handler_id, fleet, hub_url}}` → дрон пишет привязку в
   `/data/binding.json` (событие `bound`, в т.ч. `persisted:true/false`).
4. «Отвязать» — обратная операция (`COMMAND {unbind}` + стирание файла).

LED-команды работают и на паузе (мигнуть бортом во время замены АКБ, чтобы
не перепутать, куда ставить какой аккумулятор).

## Bridge-нода на железе

`bridge/ros2/bridge_node.py` — одна нода на оба флота поверх фасада
`sverk_interfaces` вашей репы sverk-ros2 (main, с ros2_mcp):

| эндпоинт | city | painter | реализация |
|---|---|---|---|
| `/pose` | ✓ | ✓ | `get_telemetry(BRIDGE_FRAME)` → клетка (`CELL_SIZE_M`, `FIELD_ORIGIN_*`) |
| `/takeoff`, `/land` | ✓ | ✓ | взлёт **в aruco-кадре** (hold текущих x,y по маркерам + подъём; body — только аварийный подскок `TAKEOFF_BODY_FALLBACK`, с немедленным перехватом в aruco) / `land()` |
| `/led` | ✓ | ✓ | `led.set_effect(effect, r,g,b)` |
| `/move` | ✓ | ✓ | `navigate_wait` к центру клетки / точке холста |
| `/photograph {cell}` | ✓ | — | `image.take_picture()` → JPEG в артефакты |
| `/analyze` | ✓ | — | бортовой VLM: ros2_mcp `POST /call vlm_query` (`ROS2_MCP_URL`, :9092) |
| `/spray` | — | ✓ | `gpio.servo_enable/servo_set_angle` (углы `SPRAY_ON/OFF_DEG`) + полёт по точкам |

**Всё движение — в кадре ArUco** (`BRIDGE_FRAME`, по умолчанию `aruco_map`):
на поле стоят маркеры позиционирования, и перелёты/взлёт/удержание считаются
в их системе координат. Body не используется для движения — только как
аварийный подскок на взлёте, если маркеры с земли не видны
(`TAKEOFF_BODY_FALLBACK=1`), с немедленным перехватом в aruco после набора
высоты; без aruco-телеметрии после взлёта нода отвечает ошибкой, а не летит
вслепую.

Чужой для режима эндпоинт → 409. Сборка: `bridge/ros2/Dockerfile`
(`--build-arg SVERK_ROS2_IMAGE=<ваш образ>`); на дроне — `network host`, чтобы
видеть PX4 DDS и `ros2_mcp`. **Проверить на стенде**: имя кадра
(`BRIDGE_FRAME`, по умолчанию `aruco_map`), знаки осей, серво-углы
краскопульта, высоты (`FLIGHT_ALT_M`, `PAINT_ALT_M`).
