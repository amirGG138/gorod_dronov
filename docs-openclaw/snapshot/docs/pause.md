# Пауза всех сценариев (замена аккумуляторов)

Оператор в любой момент ставит миссию на паузу: **дроны садятся** (bridge
`/land`), фазовая машина замирает, дедлайны не горят. После замены
аккумуляторов пауза снимается: **дроны взлетают** (bridge `/takeoff`), каждый
**ресинкает свою реальную позицию** из бриджа (`GET /pose` — после замены борт
могли переставить, верим телеметрии, а не памяти), владелец фазовой машины
сдвигает дедлайн текущей фазы ровно на длительность паузы. Работает для всех
задач: survey, safe_passage, painting, debate (там, где бриджа нет, агент
просто замирает).

## Как поставить / снять

| способ | команда |
|---|---|
| Кнопка на дашборде | `:8080/survey` → «⏸ Пауза» / «▶ Продолжить» |
| CLI (local и docker с доступным viz) | `make pause` / `make resume` (учитывает `VIZ_PORT`, `HUB_TOKEN`) |
| Docker-демо (viz монтирует доску read-only) | `make pause-docker` / `make resume-docker` (пишет через контейнер координатора) |
| HTTP напрямую | `POST /pause` с заголовком `x-pause: 1` (+ `authorization: Bearer $HUB_TOKEN`, если задан), тело `{"paused": true|false, "reason": "…"}` |

## Что происходит под капотом

1. Оператор пишет `state/pause.json` `{"paused": true, "reason", "by", "ts"}`
   (single-writer: этот файл принадлежит оператору/хабу; агенты только
   читают). Событие `{"kind":"pause"}` уходит в `events.jsonl` — дашборды
   показывают баннер.
2. Каждый агент в начале цикла (`agent/loop.py`) читает паузу:
   * **вход в паузу** — роль с бриджем вызывает `POST /land` (событие
     `pause_land`), свой `progress.status` становится `paused`
     (прежний статус сохраняется в `prev_status`), затем агент молчит;
   * дрон, исполняющий многоклеточный план (survey), **прерывает план между
     действиями и внутри `wait`** (`{"do":"abort","reason":"pause"}` в
     results) — остаток хода не исполняется;
   * мок-бридж в посаженном состоянии отвечает **409** на
     `/photograph|/move|/spray` — агент, прозевавший паузу, получит явную
     ошибку, а не тихое действие (§11).
3. **выход из паузы** — `POST /takeoff`, затем `GET /pose`: агент продолжает с
   ФАКТИЧЕСКОЙ клетки (событие `pause_resume {pose}`), `progress.status`
   восстанавливается из `prev_status`; координатор/модератор сдвигает
   `phase.deadline` на длительность паузы (событие `pause_shift {secs}`).
   Прерванная верификация продолжается: очередь и голоса не теряются
   (пропуск проверяющего по таймауту обратим — опоздавший VERIFY считается).
4. `reset_runtime` (новый запуск) стирает `pause.json` — застрявшая пауза не
   замораживает следующий прогон.

Проверено e2e (mock): пауза посреди облёта на 87 с — все 5 бортов сели,
доска полностью замерла (0 сообщений, 0 новых клеток), после резюма дроны
взлетели с ресинком позы, прерванная верификация довелась, миссия дошла до
`PASS: груз подтверждён…, ровер прибыл`.

## Железо (ROS2)

Контракт бриджа получил два новых эндпоинта — `/land` и `/takeoff` (см.
[bridge](bridge.md)). В реальном узле (`bridge/ros2/bridge_node.py`) их нужно
привязать к сервисам/экшенам takeoff/land вашей ROS2-сборки; ключевое
требование: **после взлёта `GET /pose` обязан отдавать фактическую позицию**
(AMCL/odom после ре-локализации) — на этом держится «дрон продолжает с того
места, куда его поставили». Rover на паузе просто держит позицию (для
наземного борта `land` = hold).
