# Памятка на площадку

Что запускать, в каком порядке, что должно появиться на экране и что делать, если
пошло не так. Пишется заранее — в день зачёта читать документацию некогда.

Сейчас закрыты этапы 0–2: мозг диспетчера, связь по сети и программа для дрона-монитора.
Ровер и микродрон сюда добавятся, когда до них дойдёт очередь.

Если некогда читать: **`python3 -m city.run --sim`** — проверить, что всё цело;
**`python3 -m city.pult`** — поднять дрон и командовать им с клавиатуры (пункт 3.3).

## 1. Проверка без железа (30 секунд)

Делается перед любым выездом — убеждаемся, что программа цела.

```bash
cd ~/Desktop/gorod_dronov
python3 -m city.run --sim          # вся попытка прокручивается за секунду
python3 -m unittest discover -s tests   # должно закончиться словом OK
```

Что должно быть видно: строка `PLAN_CHOSEN` с объяснением, `CHARGED` с расчётом заряда,
пары «башня 3 секунды → подъезд к пожару», затем `FIRE_EXTINGUISHED` и `DONE`.
Внизу — путь к файлу лога. Миссия в логе одна: «Доставку» команда не выполняет (PLAN.md).

## 2. Проверка связи без железа

Три окна терминала. В первых двух — «понарошечные» робот и дрон, в третьем — диспетчер.

```bash
# окно 1
python3 -m city.robots.mock_server --role rover --port 8010
# окно 2
python3 -m city.robots.mock_server --role drone --port 8020 --cell 1,1 --name m1
# окно 3
python3 -m city.run --net --drones --monitors m1
```

Это тот же прогон, что в пункте 1, но команды идут по сети и в реальном времени
(полторы-две минуты). Если он проходит — сеть, ожидания и проверки в порядке, и на
железе останется только заменить адреса.

## 3. Дрон-монитор: первый запуск

### 3.1. Безопасность — до того, как подключать батарею

- [ ] Пропеллеры ставятся **последними**, перед самым взлётом. Все настройки и
      проверки — без пропеллеров.
- [ ] Пульт включён и в руках у человека, который **не** сидит за ноутбуком.
      Аварийное отключение (KILL SWITCH) — тумблер SD.
- [ ] В полётной зоне никого.
- [ ] Батарея заряжена: регламент требует не меньше 40 %. Для 3S LiHV полный заряд
      13,05 В, в полёте не опускаться ниже 10,65 В.
- [ ] Порядок включения: сначала пульт, потом батарея дрона. Выключение — наоборот.

### 3.2. Узнать адрес дрона

Дрон — это маленький компьютер в сети. Нужен его адрес вида `192.168.1.50`.
Способы, по убыванию удобства:

1. Спросить у того, кто настраивал сеть (на площадке — у организаторов).
2. Открыть в браузере веб-интерфейс дрона — если он открывается, адрес в строке браузера.
3. Проверить, что адрес рабочий: `ping 192.168.1.50` — должны идти ответы.

Дальше в командах вместо `АДРЕС` подставляйте этот адрес.

### 3.3. Пульт — одна команда вместо трёх окон

Обычный способ работы. Всё, что расписано дальше в пунктах 3.4–3.7, эта команда делает
сама: кладёт на дрон свежую программу, запускает её, зовёт её по сети и показывает
сообщения борта. Пункты 3.4–3.7 нужны, только если пульт почему-то не пошёл.

```bash
python3 -m city.pult
```

Через полминуты в том же окне:

```
[10:55:01] дрон 192.168.1.105: проверяю связь
[10:55:02] программа на борту обновлена
[10:55:02] запускаю программу на борту (ROS поднимается небыстро, это нормально)
  борт | [07:55:01] дрон на связи, камера готова (цвет: bgr)
  борт | [07:55:01] агент «m1» слушает порт 8020
[10:55:02] зову борт: http://192.168.1.105:2200
[10:55:02] готово. Дрон ждёт команд
[10:55:02] стоит на земле, высота 0.0 м, клетка [1, 1], камера готова
команда>
```

Дальше просто печатаете команды в это же окно:

| Команда | Что делает |
|---|---|
| `статус` | что с дроном сейчас |
| `кадр` | снять фотографию, сохранить и открыть её |
| `взлет` | подняться на 1,5 м (`взлет 1.2` — на другую высоту) |
| `сесть` | посадка |
| `стоп` | аварийная посадка немедленно |
| `выход` | посадить, всё выключить и выйти |

Хватает и первой буквы: `с`, `к`, `в`, `п`.

Перед первым за запуск взлётом пульт покажет предполётный список и попросит напечатать
«да» — это защита от случайного взлёта, а не формальность.

Сообщения борта («ВЗЛЁТ», «вишу», «ПОСАДКА», «СТОРОЖ») приходят в это же окно с пометкой
`борт |`, так что второе окно не нужно.

Выход по `выход` или `Ctrl+C` **сажает дрон, если он в воздухе** и останавливает
программу на борту. Другой дрон — `python3 -m city.pult --ip 192.168.1.107
--name m2 --cell 4,1`.

### 3.4. Положить программу на дрон

Один раз на новом дроне — вход без пароля (пароль спросит только сейчас, дальше никогда):

```bash
ssh-copy-id -i ~/.ssh/id_ed25519_1schedule.pub sverk@АДРЕС    # пароль: sverk
```

Копируем обе программы — саму бортовую и пусковой скрипт к ней:

```bash
ssh sverk@АДРЕС 'mkdir -p ~/gorod_dronov/onboard'
scp onboard/drone_agent.py onboard/run_agent.sh sverk@АДРЕС:~/gorod_dronov/onboard/
ssh sverk@АДРЕС 'chmod +x ~/gorod_dronov/onboard/run_agent.sh'
```

Зайти на дрон: `ssh sverk@АДРЕС`. Вы окажетесь **внутри контейнера** — это то, что нужно.

### 3.5. Запустить

На дроне (в том окне, где вы по `ssh`):

```bash
cd ~/gorod_dronov && ./onboard/run_agent.sh --name m1 --cell 1,1
```

**Запускать только через `run_agent.sh`.** Просто `python3 drone_agent.py` на борту не
работает: системному питону сломали `cv2` (поверх старого numpy доставили новый), а
`sverk_interfaces` виден только после двух команд `source`. Скрипт делает и то, и другое.

Должно появиться:

```
[12:30:01] подключаюсь к дрону…
[12:30:03] дрон на связи, камера готова (цвет: bgr)
[12:30:03] агент «m1» слушает порт 8020
```

**Строка «камера НЕ ГОТОВА» — это сразу стоп.** Кадров не будет, а без кадров дрон-монитор
бесполезен. Не взлетайте, разбирайтесь с камерой.

Окно с этой программой должно оставаться открытым. Закроете — дрон перестанет принимать
команды (и, если он в воздухе, сядет сам через 8 секунд).

Остановить: `Ctrl+C` в этом окне. Если программа осталась работать с прошлого раза
(при запуске пишет `ПОРТ 8020 УЖЕ ЗАНЯТ`), убить её с ноутбука:

```bash
ssh sverk@АДРЕС 'pgrep -af "[d]rone_agent"'      # посмотреть, что запущено
ssh sverk@АДРЕС 'pkill -9 -f "[d]rone_agent"'    # остановить
```

Квадратные скобки — не опечатка и не украшение: без них команда находит саму себя и
обрывает соединение раньше, чем доберётся до агента. И именно `-9`: обычный `kill`
эту программу не берёт.

### 3.6. Два номера порта — не перепутать

Программа на борту сидит **внутри контейнера** и слушает порт **8020**. Снаружи этот порт
виден под другим номером — **2200**. Так настроено на всех дронах и сохраняется после
перезагрузки.

Отсюда правило: на дроне — 8020, с ноутбука и с других дронов — **2200**.

```bash
curl http://АДРЕС:2200/status      # так дрон зовут снаружи
```

Ничего запускать и держать открытым для этого не надо. Если ответа нет, а на самом дроне
(`curl http://127.0.0.1:8020/status` в окне `ssh`) всё отвечает — значит на этом борте
проброс не настроен, спрашивайте того, кто настраивал дрон.

### 3.7. Проверить с ноутбука — сначала на земле

```bash
curl http://АДРЕС:2200/status
```

Ответ должен содержать `"state": "idle"` и `"camera": true`.

Кадр **без взлёта** — самая ценная проверка, делайте её обязательно:

```bash
curl http://АДРЕС:2200/shot -o kadr.jpg
open kadr.jpg
```

Открылась фотография пола — камера, сеть и сжатие работают. Дальше можно летать.

Отдельно посмотрите на **цвета** — но сверяйтесь с предметом, цвет которого точно знаете
(лента, коробка, ваша куртка), а не «на глаз по полу»: пол в помещении сам может быть
синим, и тогда правильный кадр выглядит подозрительно. Если красное в кадре выходит синим,
а синее красным — перезапустите программу с `--color rgb`. На наших дронах проверено:
правильно `--color bgr`, это и стоит по умолчанию.

### 3.8. Первый полёт

Пропеллеры на месте, пульт РУ в руках у второго человека, зона пустая.

В пульте (пункт 3.3) это четыре слова подряд:

```
команда> взлет          → пульт покажет список и спросит «да»
команда> статус         → должно быть «висит, высота 1.5 м»
команда> кадр           → снимок с высоты откроется на экране
команда> сесть          → «дрон сел»
```

Тем же в обход пульта, если он не пошёл:

```bash
curl -X POST http://АДРЕС:2200/takeoff -d '{"alt":1.5}'   # взлёт на 1,5 м
curl http://АДРЕС:2200/status                              # ждём "state": "hover"
curl http://АДРЕС:2200/shot -o pole.jpg                    # кадр с высоты
curl -X POST http://АДРЕС:2200/land                        # посадка
```

Дрон отчитывается о каждом шаге: `ВЗЛЁТ на 1.5 м`, `вишу на 1.5 м`, `ПОСАДКА`.

### 3.9. Проверить сторожа (тоже полёт)

Взлететь и **ничего не делать 10 секунд** (в пульте — просто не печатать). Дрон должен
сесть сам, а на экране появится `СТОРОЖ: 8 с без команд с ноутбука — сажусь сам`. Это
требование регламента про отключение при потере связи, и это же спасёт аппарат, если
ноутбук зависнет.

### 3.10. Полёт под управлением диспетчера

Это уже вся система целиком, а не ручные команды.

Оставьте пульт открытым — он держит программу на борту. Во **втором окне**:

```bash
python3 -m city.run --net --drones --monitors m1 --drone-url http://АДРЕС:2200
```

**Пока идёт прогон, в пульт ничего не печатайте** — двое командующих одним дроном ни к
чему хорошему не приведут. Пульт в это время работает окном отчёта: строки борта видны там.

Дрон взлетит, снимет кадр, сядет; кадр окажется в `logs/shots/`, а в логе появится строка
`ROBOT` с адресом настоящего дрона.

## 4. Строка на экране → что случилось → что делать

| Строка | Что это значит | Что делать |
|---|---|---|
| `камера НЕ ГОТОВА` | нет библиотек или патча камеры | не летать, разбираться с камерой |
| `нет входа по ssh` | ключ на этот дрон не залит | одна строка из пункта 3.4 |
| `борт не отозвался за 40 с` | дрон выключен, не в сети или ROS не поднялся | `ping`, питание, подождать и повторить |
| `ПОРТ 8020 УЖЕ ЗАНЯТ` | программа на дроне уже запущена | пульт решает сам; вручную — пункт 3.5 |
| `ModuleNotFoundError: sverk_interfaces` | запустили не через `run_agent.sh` | запускать скриптом |
| красное в кадре синее | камера отдаёт цвета наоборот | перезапустить с `--color rgb` |
| с ноутбука нет ответа, с дрона есть | на этом борте нет проброса 2200 | пункт 3.6, спросить того, кто настраивал дрон |
| `ROBOT … нет связи` | борт не ответил диспетчеру | проверить адрес и `ping`, включён ли дрон |
| `ВНИМАНИЕ: на том конце программа-заглушка` | дрон запущен с `--dry` | перезапустить без `--dry`, этот прогон не считается |
| `409 занят` | пришла вторая команда, пока идёт первая | это защита, а не поломка: дождаться конца |
| `взлёт не принят` | дрон не встал в OFFBOARD или не заармился | проверить пульт, `selfcheck`, батарею |
| `ПОСАДКА НЕ ПОДТВЕРЖДЕНА` | команда посадки не сработала | **сажать пультом**, дальше не командовать |
| `СТОРОЖ: … сажусь сам` | нет команд с ноутбука | норма при обрыве; проверить сеть |
| `DWELL … НЕ ЗАСЧИТАНО` | стоянка не засчитана по регламенту | смотреть на `moved` и `led` в той же строке |
| `ENERGY_BLOCK` | у ровера кончился игровой заряд | ошибка расчёта бюджета, смотреть строку `CHARGED` |

## 5. Аварийная остановка

По убыванию скорости:

1. **KILL SWITCH на пульте РУ** (тумблер SD) — мгновенно и всегда. Дрон падает, зато
   никого не порежет.
2. Слово `стоп` в пульте — дрон садится сам. Одна буква и Enter, руки уже на клавиатуре.
3. `Ctrl+C` в пульте — сажает дрон и всё выключает.
4. `Ctrl+C` в окне диспетчера — диспетчер глушит все аппараты.
5. Без пульта: `curl -X POST http://АДРЕС:2200/stop`.
6. Совсем крайнее: `ssh sverk@АДРЕС 'pkill -9 -f "[d]rone_agent"'` — программа на борту
   умирает, и дрон садится сам через 8 секунд по сторожу.

## 6. Что уже проверено на живом дроне

Наземная сверка на борту `192.168.1.105`, 2026-07-28 (без взлёта):

- программа на борту запускается, камера отдаёт кадры (`camera: true`, снимок 180–200 КБ);
- цвета правильные без перестановки каналов (`--color bgr`);
- дрон отвечает с ноутбука, кадр долетает (в тот день — через туннель; проброс 2200
  появился позже, и туннель больше не нужен);
- пульт проходит весь путь: обновил программу → запустил → снял кадр → всё выключил;
- защита от второго запуска на занятом порту работает и объясняет себя по-русски.

**Не проверено ничего, что требует воздуха:** сам взлёт, удержание высоты, посадка,
сторож в полёте, размер метки на поле. Это первое, что нужно сделать с пультом в руках.
