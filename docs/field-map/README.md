# ArUco-карта нашего полигона

Файл `map.txt` — карта маркеров поля «Города дронов», в формате `aruco_map_node`
(Обрик ROS 2). Получен 2026-07-27, обновлён 2026-07-28 (исходно лежал в корне
как `cyty_drone.txt`, обновление пришло как `city_drone.txt`).
На железе **ещё не проверялся** — сверить в первый день на площадке.

```
# id    length  x       y       z       rot_z   rot_y   rot_x
50      0.25   -1.2     1.2     0.0     0.0     -0.0    0.0
60      0.25    1.2     1.2     0.0     0.0     -0.0    0.0
62      0.25   -1.2    -1.2     0.31    0.0     -0.0    0.0
7       0.25    1.2    -1.2     0.31    0.0     -0.0    0.0
```

**Что изменилось 2026-07-28:** маркеры 62 и 7 (сторона поля `y = −1.2`) подняты
на `z = 0.31` м. Всё остальное — id, размер, `x`/`y`, повороты — не менялось.

Колонки (`docs/sverk/obrik-ros-2/_ВСЁ.md:14750`): `id`, сторона маркера в метрах,
`x y z` центра в метрах, `yaw pitch roll` в радианах. Все повороты нулевые —
маркеры лежат горизонтально, нормаль вверх; но **не все на полу**: два из четырёх
на высоте 0,31 м.

## Что из этого следует

**Четыре маркера, сторона 25 см, шаг 2,4 м по обеим осям.**
Начало координат `map`/`aruco_map` — в центре квадрата из маркеров, то есть в
центре поля (стартовая зона = игровая зарядка). Диагональ между
противоположными маркерами 3,39 м.

**Маркеры стоят по центрам клеток поля.** Поле 6×6 по 80 см; центры клеток
отстоят от центра поля на ±0,4, ±1,2, ±2,0 м. Наши ±1,2 м — это ровно клетки с
индексами 1 и 4 по каждой оси (0-based):

| id | x, м | y, м | z, м | клетка (col, row), 0-based |
|---|---|---|---|---|
| 50 | −1.2 | +1.2 | 0.0 | (1, 4) |
| 60 | +1.2 | +1.2 | 0.0 | (4, 4) |
| 62 | −1.2 | −1.2 | **0.31** | (1, 1) |
| 7  | +1.2 | −1.2 | **0.31** | (4, 1) |

Это те же четыре клетки, что в реконструкции OpenClaw (`[1,1] [4,1] [1,4] [4,4]`,
240 см между центрами) — то есть площадки на крышах домов под дроны-мониторы.
Оговорка после обновления карты: «на крышах» подтвердилось только для двух из них
(id 62 и 7, `z = 0.31`); под id 50 и 60 с `z = 0` дома может и не быть — это
единственный оставшийся повод сомневаться в списке `buildings` в `city/config.yaml`.
Расхождения с их гипотезой: **id 51–54 → на самом деле 50, 60, 62, 7**, и
**сторона 29 см → 25 см**. Их `test_fixtures/city-1/map.json` в этих двух полях
править перед любым использованием.

Пересчёт «клетка → метры» для диспетчера (центр поля = 0,0):

```
x = (col - 2.5) * 0.8
y = (row - 2.5) * 0.8
```

## Поле разновысотное: две площадки на 0,31 м

Пара маркеров с `y = −1.2` (id 62 и 7) поднята на 31 см над плоскостью двух
других. Читается это как «две площадки лежат на крышах домиков, две — на полу»;
что именно стоит под ними, проверять на площадке. Практические следствия:

- **Нулевая высота карты = пол.** Начало координат `map` остаётся там же, в
  центре поля на полу (`z=0`). Высота, которую отдаёт `aruco_map`/EKF2, — от
  пола, а не от крыши: подъём маркера учтён внутри карты, отдельной поправки в
  коде диспетчера не нужно.
- **Садиться на такую площадку — это садиться на 31 см выше пола.** Целевая
  высота посадки и порог «сел» у любого автомата снижения относительно `map`
  должны считаться от 0,31, иначе дрон будет «дожимать» в крышу.
- **Оценка высоты по размеру метки в кадре даёт высоту над самой меткой**, а не
  над полом. У `hold_aruco` (`alt_by_side`) над id 62/7 это 31 см разницы; при
  перескоке между разновысотными метками оценка `h≈` скачком меняется на ту же
  величину, хотя дрон не двигался по вертикали (`hold_aruco/README.md`).
- **Потолок 4 м по регламенту меряется от пола**, то есть над крышевой площадкой
  запас по высоте на 31 см меньше.

## Ловушки

- **Словарь не `DICT_4X4_50`.** id 62 и 60 в него не влезают (нужны id < 50).
  Параметр `dictionary_id` ноды `aruco_detect_node` по умолчанию `3`
  (`DICT_4X4_1000`) — он подходит; выставлять `0` из примеров документации
  **нельзя**. В нашем коде «Змейки» жёстко зашит `DICT_4X4_50`
  (см. `docs/zmeyka.md`) — при переносе менять.
- **Метка в кадре будет далеко не всегда.** Четыре маркера на 4,8 м поля с шагом
  2,4 м: на рабочей высоте камера вниз обычно видит один маркер или ни одного.
  Вся навигация «Змейки» построена на том, что метка видна почти всегда — сюда
  она в таком виде не переносится. `pnp.min_used_markers` по умолчанию `1`, то
  есть позиция по одному маркеру считаться будет, но yaw по одной метке шумный.
- **`marker_size` ноды детектора (дефолт 0,5 м) — только фолбэк** для маркеров,
  которых нет в карте. Наши четыре берут размер из файла.
- **Маркеров миссий здесь нет.** В карте только четыре напольных/крышевых
  маркера локализации. Маркер с числом заездов за водой (миссия «Пожар») в этот
  файл не входит и в карту его класть не надо — он распознаётся детектором как
  посторонний.

## Как использовать на борту

Файл карты на дроне: `~/sverk_ws/src/sverk_drone/odometry/aruco/aruco_map/config/sverk.txt`
(в документации путь встречается и как `odomerty/…` — опечатка апстрима, см.
«Замеченные проблемы» в `docs/sverk/README.md`). Нода читает карту один раз при
старте, динамического переключения нет:

```bash
ros2 run aruco_map aruco_map_node --ros-args -p map_file:=config/map.txt
ros2 topic echo /aruco_map/pose_cov      # проверка, что локализация поехала
```

Визуальная проверка карты — веб-интерфейс → Web video server → топик
`aruco_map/debug_image/plane_1` (рисует оси в нулевой точке карты).
