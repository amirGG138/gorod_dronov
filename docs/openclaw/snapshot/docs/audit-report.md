## TL;DR

1. **Главный смысловой баг:** в дефолтном режиме `curated` куратор рисует картину
   **не видя переговоров** — он читает сообщения типа `PROPOSAL`, которых в новом
   «кирпичном» потоке вообще нет. Весь спор дронов выбрасывается.
2. **mock-мозг немой:** при `MODEL_PROVIDER=mock` (дефолт в compose) дроны не спорят —
   каждая реплика это хардкод-`fallback`-шаблон. Настоящий спор есть только с реальным
   провайдером (в `.env` сейчас `sverk/qwen35` — но compose поднимает `mock`).
3. **Картинка превращается в кашу:** нет z-порядка, всё непрозрачно, рисуются полилинии
   вместо заливок, а мост ещё и пририсовывает паразитные линии через холст.
4. **Хардкод 4 персон зашит в ~7 местах** — 5-й дрон ломается или деградирует.

## A. Баги (по убыванию серьёзности)

### A1 — [CRITICAL] curated-куратор не видит переговоров
`agent/roles/coordinator_paint.py:43-55` — `_proposals_brief()` фильтрует
`m.get("type") != "PROPOSAL"`. Но в текущем потоке художники постят `BRICK`
(`painter.py:46`), `BUILD`, `VOTE` — `PROPOSAL` нет нигде. Итог: промпт куратора
всегда получает `«(нет предложений)»`, и вся картина строится только из строки
`subject`. Кирпичи/черновик/спор — мимо. **Чинить:** читать `BRICK`+`BUILD`+`collaborative.json`.

### A2 — [HIGH] mock-мозг возвращает пустоту → нет настоящего спора
`agent/brain.py:446-447` `chat()` → `return ""`; `:432` `think_json` → `None`;
`:84` `chat_json_with_retry` → `None`. При `MODEL_PROVIDER=mock`
(`docker-compose.painters.yml:38` дефолт) **весь** диалог — детерминированные
`fallback`-словари из `painter_agent.py` (`:242-250`, `:283-291`, `:327-332`).
README обещает «real disagreement» — этого в mock нет. `.env` ставит `sverk`, но
`make demo-painters` использует compose-дефолт `mock`, если не передан провайдер.

### A3 — [HIGH] нестабильный/невоспроизводимый tie-break голосования
`agent/roles/coordinator.py:438` ключ сортировки `hash((s, paint_seed)) & 0xFFFF`
и `agent/roles/paint_shapes.py:287` `hash(subject) % 10007` используют встроенный
`hash()` строк — он солится `PYTHONHASHSEED` и **различается между процессами/запусками**.
`docs/debugging-painters.md` и README обещают воспроизводимость по seed — её нет.
**Чинить:** `_seed()` (sha256) уже есть в `painter_compose.py` — использовать его.

### A4 — [HIGH] валидатор куратора жёстко требует painter-1..4
`agent/roles/coordinator_paint.py:58-72` `_validate_curated` требует ровно 4 слоя
и `painter-1..painter-4`. При любом другом наборе painters (5 дронов, переименование,
Pi-узел `painter-7`) валидация не проходит → ретраи до `CURATED_COMPOSE_TIMEOUT`
(180с) → процедурный fallback. Тихая деградация + долгое зависание EXECUTE.

### A5 — [MED] execute_curated тянет цвет/технику из статичного ROSTER
`agent/roles/coordinator_paint.py:138,169-172` — `roster = {p["id"]: p for p in ROSTER}`,
затем `roster.get(pid, {}).get("hex","")`. Для дрона вне `painter-1..4` прогресс
получает пустой цвет и технику; на дашборде палитра/подписи ломаются.

### A6 — [MED] стриминг «мыслей» художников — не token-by-token
`agent/loop.py:228-233`: для painter с реальным мозгом ветка идёт в
`emit_thought_precooked` (т.к. `thinking is not None`), т.е. CoT нарезается **постфактум**
фиксированными кусками, а не стримится живьём. README (§dashboard) обещает
«streams chain-of-thought token-by-token with blinking cursor» — для художников это не так
(так работает только `emit_thought` у scout/rover).

### A7 — [MED] novelty-gate мёртв для художников
`agent/loop.py:239` `gated_types = {"PROPOSAL"}`. Художники шлют `BRICK/BUILD/VOTE` —
гейт их не трогает, дубликаты-кирпичи не отсекаются. README §novelty-gate описывает
отсев пропозалов — к painters не применяется.

### A8 — [LOW] мёртвый код / рассинхрон
- `agent/roles/painter_agent.py:43` и `:91` — `_inspiration` объявлен дважды.
- `agent/roles/coordinator.py:417-421` — поля `invalid` (всегда `False`) и
  `for_author` (всегда «общий вариант») ничего не делают.
- `agent/roles/painter_compose.py` — `COMPOSE_PLAN_MAX_CHARS` импортирован, не используется.
- `drone/entrypoint.sh:15` — `DRONE_SUBJECT` заявлен в шапке, но **нигде не читается**;
  `MOOD` (`:44`) не имеет env-override в отличие от COLOR/TECHNIQUE/NAME.
- README §painters всё ещё описывает «слой = sky/water/light/foreground» и квадранты,
  а код давно перешёл на curated/abstract + brick-flow. `docs/debugging-painters.md`
  ближе к коду, README — устарел.

### A9 — [LOW] палитра-фильтр режет сюжеты
`agent/roles/painter_palette.py:43-49` `FORBIDDEN_COLOR_RE` блокирует фиолетовый,
розовый, бирюзу, **коричневый, бежевый**. Сюжеты «дерево/изба» (коричневый ствол)
формально подпадают под запрет → `sanitize_subject` может откатить к fallback.

## B. Почему картинка выглядит «сложной»/нечитаемой и как починить

(подтверждено чтением `viz/index.html:507-528`, `bridge/mock.py:221-240`)

**Корни проблемы:**
- **Нет z-порядка.** `drawPainting()` рисует `STROKES` в порядке прихода событий
  (`index.html:520`). Фон одного дрона может лечь поверх переднего плана другого —
  фигуры/фон не структурированы → «каляки».
- **Всё полностью непрозрачно, поверх друг друга.** `globalAlpha`/`compositeOperation`
  не трогаются (`index.html:522`); каждый следующий мазок затирает предыдущий.
- **Рисуются только полилинии (`ctx.stroke`), нет заливок.** Солнце/дом/дерево как
  сплошную массу получить нельзя — только тонкие ленты.
- **Densify плодит тысячи микро-сегментов** (`painter_compose.densify_strokes`,
  бюджет до 1200 на дрона × N) → «густой войлок».
- **Мост пририсовывает паразитные линии:** `bridge/mock.py:235` подставляет текущую
  позу первой точкой каждого `spray`, соединяя несвязанные мазки длинными перелётами.

**Рекомендации (по убыванию отдачи):**
1. **Перейти от «спрея полилиний» к декларативным фигурам с z-слоем.** Событие
   `{"kind":"shape", type, fill, points|cx/cy/r, color, z, alpha}`; на канвасе
   `STROKES.sort((a,b)=>(a.z||0)-(b.z||0))` перед отрисовкой и `ctx.fill()` для
   заливок. Словарь фигур уже есть (`paint_shapes.py` + `COLLAB.bricks[].shapes`) —
   рендерить его напрямую, без densify.
2. **Фиксированный порядок «фон→земля→объекты».** Даже без z — сортировать по роли слоя.
3. **Per-layer alpha** для атмосферы (небо/дымка), передний план — alpha 1.
4. **Убрать pose-prepend** в `mock.py:235` (или флаг `pen_up`), чтобы не было перелётных линий.
5. **Меньше, крупнее.** 6-15 крупных заливок читаются как картинка лучше тысяч штрихов;
   поднять множитель ширины (`index.html:522` `*0.6`).
6. **Вариант SVG.** Раз финал — это десяток фигур, `<rect>/<circle>/<polygon>` дают
   нативный z-order (порядок документа) и чистые заливки. Хорошо ложится на «просто и узнаваемо».

> Итог: цель «достаточно просто, чтобы наша рисовалка справилась» достигается не
> ограничением фантазии дронов, а **сменой примитива рендера** (фигуры+z вместо
> спрей-полилиний). Тогда дроны могут спорить о чём угодно, а на холст ложится
> чистая композиция из нескольких заливок.

   дефолт реальным провайдером.
5. **Рендер фигур+z** (раздел B) — чтобы «просто и узнаваемо» при любых сюжетах.

персоны: из soul или из seed; mock: оживить или требовать реальный LLM).

## F. Разбор «плохого рана» (по логам реального запуска) и фиксы

Симптомы пользователя: уродливая картинка (2 эллипса + звезда), ошибки «Пустой
ответ модели… 2/3, 3/3», вырожденный дебат (все голосуют за один generic-вариант).

**Корневая причина (из `llm.jsonl`):** ВСЕ LLM-вызовы падали по таймауту —
`painter chat = 90с TimeoutError, resp_len=0`; `curated_compose = 180с ×3, пусто`.
Прямой тест шлюза показал: **`qwen35` — reasoning-модель, которая «думает вслух»
в `content` на английском** и при любом `max_tokens` НЕ доходит до JSON
(`finish=length`). На больших выводах рамблит за таймаут.

**Решение (проверено вживую):** добавить в запрос
`chat_template_kwargs:{enable_thinking:false}` + `enable_thinking:false`
(`agent/brain.py:_no_think_params`, env `LLM_THINKING=1` чтобы вернуть CoT).
После этого qwen35 отвечает **за 4-18с валидным JSON** (вместо 90с пустоты).

**Сопутствующие фиксы:**
- **Гонка дедлайнов:** фазы (propose 30с) были КОРОЧЕ таймаута вызова (90с) —
  машина убегала вперёд, кирпичи/голоса не успевали лечь → всё в fallback.
  Дедлайны увеличены и вынесены в env (`loop.py`: propose 90, build 150,
  converge 90, execute 240).
- **Именованные цвета (запрос пользователя):** случайный hex был бессмыслен для
  модели. Введена палитра named-пигментов (`personas.PALETTE`: янтарный, лазурный,
  изумрудный…). Агент знает «я рисую лазурным» и рассуждает осмысленно.
- **Цвето-семантическая композиция** (`paint_shapes.compose_by_color`): роли сцены
  раздаются художникам по близости hue (синий→вода/небо, зелёный→листва,
  янтарь→солнце) — картинка когерентна по цвету. Это и надёжный fallback.
- **Уродливый generic-fallback** (2 эллипса+звезда) заменён на приятный пейзаж
  (небо/солнце/вода/земля).
- **Anti-sparse:** если LLM дал мало фигур — холст обогащается колор-базой.

**Проверка вживую (после фиксов):** `OK: chat=16, curated_compose=1, ERR: {}`
(было — сплошные таймауты); bricks=4, candidates=3 (реальный дебат);
финальный холст — **10 залитых z-упорядоченных фигур** разных типов вместо каши.
