# YOLO: принцип работы


YOLO (You Only Look Once) — семейство нейронных сетей для обнаружения объектов в реальном времени.


Классические алгоритмы обработки изображений анализируют кадр в несколько проходов: сначала ищут области, где может быть объект, затем классифицируют каждую область. YOLO делает всё за один проход — отсюда название. Сеть делит изображение на сетку ячеек и для каждой ячейки одновременно предсказывает:

- **Ограничивающий прямоугольник** — координаты x, y, ширина, высота
- **Класс объекта** — к какой категории относится (человек, машина, кошка и т. д.)
- **Уверенность** — значение от 0.0 до 1.0

Результат одного кадра выглядит так:


```
[
  { "label": "person",  "class_id": 0,  "score": 0.91, "x1": 120, "y1": 45,  "x2": 280, "y2": 310 },
  { "label": "bottle",  "class_id": 39, "score": 0.78, "x1": 400, "y1": 200, "x2": 450, "y2": 290 }
]

```


Через API микродрона это же выглядит так:


```
for det in drone.get_detections():
    print(det.label, det.class_id, det.score, det.x1, det.y1, det.x2, det.y2)

```


## Почему YOLO подходит для дрона

|  Требование |  Почему важно для дрона |  Как YOLO отвечает |
|  Скорость |  Дрон движется — задержка при обнаружении = ошибка позиции |  Один проход по сети вместо нескольких |
|  Компактность |  Слабый бортовой компьютер, нет мощной GPU (графического процессора) |  Nano-версии работают на CPU (центральном процессоре) |
|  Точность |  Ложные срабатывания = неверные решения |  Уверенность для фильтрации |
|  Реальное время |  Решения принимаются на лету |  До 30+ FPS (кадров в секунду) на nano-моделях |


## Версии YOLO

|  Версия |  Особенности |  Для микродрона |
|  YOLOv5 |  Зрелая, большая экосистема, много готовых весов |  Подходит, но старше |
|  YOLOv8 |  Улучшенная архитектура, простой Python API |  Подходит |
|  **YOLO11** |  Последнее поколение, лучшая точность |  **Рекомендуется** |


Для бортового компьютера микродрона используйте **YOLO11n** (nano) — наименьшую и быструю версию в семействе. Более крупные варианты (small, medium, large) значительно медленнее. Эту же версию использует готовый [ноутбук обучения](/learn/whoop/neural-training).


## Интеграция с микродроном

- **Камера** непрерывно снимает видеопоток.
- **Бортовой компьютер** прогоняет каждый кадр через YOLO-модель и находит объекты.
- **Ваша программа** читает результаты через `drone.get_detections()`.
- **Программа принимает решение** — зависнуть, полететь к объекту, продолжать поиск.
- **Отправляет команду** — `drone.navigate()` или `drone.set_velocity()`.

Метод `drone.get_detections()` возвращает текущий список объектов в кадре — каждый объект содержит:

- `det.label` — строковое название класса (например, `"balloon"`)
- `det.class_id` — числовой ID класса
- `det.score` — уверенность (0.0—1.0)
- `det.x1, det.y1` — левый верхний угол прямоугольника (пиксели)
- `det.x2, det.y2` — правый нижний угол прямоугольника (пиксели)
- `det.z1, det.z2` — глубина 3D-бокса (при наличии информации о дистанции)

Для большинства задач достаточно `label`, `score` и координат `x1/y1/x2/y2`.


## Пользовательские классы


Предобученные модели YOLO знают 80 стандартных классов (датасет COCO): люди, машины, животные, мебель и т. д. Для специфических задач — например, обнаружение маркировки на полу или конкретного предмета — нужно обучить свою модель на собственном датасете.


Процесс:

- Собрать изображения объекта с разных ракурсов и при разном освещении.
- Разметить объекты (нарисовать прямоугольник для каждого объекта на каждом фото).
- Обучить YOLO11n на размеченном датасете.
- Скопировать файл модели на бортовой компьютер.

Подробнее — в статьях «[Сбор датасета в Roboflow](/learn/whoop/neural-dataset)» и «[Обучение модели YOLO11](/learn/whoop/neural-training)».


## Разрешение камеры


Бортовая камера микродрона выдаёт видеопоток с разрешением **1280 × 720** пикселей. Центр кадра — точка (640, 360). Это значение важно при вычислении смещения объекта от центра кадра для управления по визуальной обратной связи:


```
FRAME_W, FRAME_H = 1280, 720
FRAME_CX, FRAME_CY = FRAME_W / 2, FRAME_H / 2  # (640.0, 360.0)

# Смещение центра прямоугольника от центра кадра (нормированное, от -0.5 до +0.5)
obj_cx = (det.x1 + det.x2) / 2
err_x = (obj_cx - FRAME_CX) / FRAME_W

```


Координаты (`x1, y1, x2, y2`) всегда приходят в пикселях этого разрешения.


## Ограничения бортового компьютера


Бортовой компьютер — энергоэффективное вычислительное устройство с ограниченными ресурсами. При использовании YOLO учитывайте:

- **Низкий FPS** — 3—10 кадров в секунду при инференсе nano-модели на CPU. Достаточно для медленного полёта, но не для быстрого маневрирования.
- **Только nano-модели** — YOLO11n или аналоги. Более крупные модели будут работать слишком медленно или не запустятся.
- **Уменьшайте разрешение входа** — инференс на 320×320 или 416×416 быстрее, чем на 640×640. Точность немного снизится, скорость вырастет вдвое.
- **Не запускайте тяжёлые фоновые процессы** — во время инференса бортовой компьютер должен иметь максимально свободные ресурсы.

Для задач, где требуется высокий FPS, рассмотрите аппаратное ускорение (ONNX Runtime с оптимизациями под архитектуру платы) или обработку на земле с передачей результатов по Wi-Fi.
