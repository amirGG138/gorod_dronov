# Обучение модели YOLO11


## Требования

|  Компонент |  Минимум |  Рекомендуется |
|  Python |  3.8+ |  3.10+ |
|  ОЗУ |  8 ГБ |  16 ГБ |
|  GPU (графический процессор) |  Не требуется (медленно) |  NVIDIA с 4+ ГБ VRAM (памяти видеокарты) |
|  Диск |  5 ГБ |  20 ГБ |


Если GPU нет — используйте **Google Colab** (бесплатный GPU T4 по несколько часов в день). Обучение на CPU занимает в 10—50 раз дольше.


## Установка


```
pip install ultralytics

```


Библиотека `ultralytics` — официальный пакет для работы с YOLOv8 и YOLO11. Содержит инструменты для обучения, валидации и инференса.


## Структура data.yaml


Пример для задачи с двумя классами:


```
path: /home/user/dataset  # абсолютный путь к датасету
train: images/train
val: images/val
nc: 2
names:
- 'red_cube'
- 'blue_cube'

```


При обучении в Google Colab используйте путь вида `/content/dataset`.


## Обучение YOLO11n


```
from ultralytics import YOLO

# Загрузить предобученную модель (скачается автоматически при первом запуске)
# yolo11n.pt — nano-версия, наименьшая и быстрейшая
model = YOLO('yolo11n.pt')

# Запустить обучение
results = model.train(
    data='data.yaml',  # путь к конфигурации датасета
    epochs=100,        # количество эпох обучения
    imgsz=640,         # размер входного изображения (пиксели)
    batch=16,          # количество изображений в одном батче
    device='cuda'      # 'cuda' для GPU, 'cpu' для процессора
)

```


Результаты сохраняются в папку `runs/detect/train/` — там находятся веса модели, графики и метрики.


## Параметры обучения

|  Параметр |  Типичные значения |  Рекомендация для Микродрона |
|  `epochs` |  50—300 |  100—150 для небольшого датасета |
|  `imgsz` |  320, 416, 640 |  640 — стандарт, 320 — если мало данных |
|  `batch` |  8, 16, 32 |  16 для GPU 4 ГБ; 8 если не хватает памяти |
|  `device` |  `'cuda'`, `'cpu'`, `'mps'` |  `'cuda'` на GPU, `'cpu'` на Colab без GPU |
|  `lr0` |  0.001—0.01 |  Оставьте по умолчанию |
|  `patience` |  50 |  Остановить, если нет улучшений N эпох |


### Добавить раннюю остановку


Чтобы не тратить время на обучение после достижения максимума качества:


```
results = model.train(
    data='data.yaml',
    epochs=200,
    imgsz=640,
    batch=16,
    device='cuda',
    patience=30  # остановить, если mAP50 не улучшается 30 эпох подряд
)

```


## Мониторинг обучения


В процессе обучения YOLO выводит метрики после каждой эпохи. Ключевые показатели:


### Loss (потери)

|  Метрика |  Что означает |  Хороший признак |
|  `box_loss` |  Ошибка предсказания bbox |  Уменьшается к концу обучения |
|  `cls_loss` |  Ошибка классификации |  Уменьшается |
|  `dfl_loss` |  Ошибка распределения |  Уменьшается |


Если loss перестал уменьшаться — обучение достигло предела с текущим датасетом.


### mAP (mean Average Precision)

|  Метрика |  Что означает |  Ориентиры |
|  `mAP50` |  Точность при IoU ≥ 0.5 |  > 0.7 — хорошо; > 0.9 — отлично |
|  `mAP50-95` |  Точность при разных порогах IoU |  > 0.5 — хорошо |


**IoU** (Intersection over Union) — степень перекрытия предсказанного bbox с реальным. При IoU ≥ 0.5 обнаружение считается верным.


### Когда остановить обучение

- Loss на validation перестал уменьшаться или начал расти — признак переобучения.
- mAP50 вышел на плато и не растёт несколько эпох.
- Используйте `patience` для автоматической ранней остановки.

Графики метрик доступны в `runs/detect/train/results.png` — рекомендуется проверять после обучения.


## Экспорт модели


После обучения основной файл весов — `runs/detect/train/weights/best.pt`. С ним можно работать на компьютере напрямую или экспортировать в ONNX, чтобы проверить инференс на другой платформе:


```
from ultralytics import YOLO

model = YOLO('runs/detect/train/weights/best.pt')

# Экспорт в ONNX
model.export(format='onnx', imgsz=640)

# Создаст файл runs/detect/train/weights/best.onnx

```


ONNX Runtime может работать быстрее нативного PyTorch на некоторых платформах без GPU.


>

**Внимание** Этого ONNX-файла недостаточно для запуска на бортовом компьютере Микродрона — плата работает только с форматом `.cvimodel`. Подготовка модели для дрона описана ниже в разделе «Перенос модели на Микродрон».


## Тест инференса


Проверьте модель на тестовом изображении перед переносом на Микродрон:


```
from ultralytics import YOLO

model = YOLO('runs/detect/train/weights/best.pt')

# Инференс на одном изображении
results = model.predict('test_image.jpg', conf=0.5)

# Вывод результатов
for result in results:
    for box in result.boxes:
        cls_id = int(box.cls)
        confidence = float(box.conf)
        x1, y1, x2, y2 = box.xyxy[0].tolist()
        print(f"Класс: {result.names[cls_id]}, уверенность: {confidence:.2f}")
        print(f"  bbox: ({x1:.0f}, {y1:.0f}) — ({x2:.0f}, {y2:.0f})")

# Сохранить изображение с нарисованными bbox
results[0].save('result.jpg')

```


## Типичные проблемы


### Переобучение (overfitting)


**Признак:** loss на обучающей выборке продолжает падать, а на validation — растёт или стоит на месте.


**Решения:**

- Увеличить датасет — добавить разнообразные изображения.
- Включить аугментацию: `augment=True` в параметрах обучения (включена по умолчанию).
- Уменьшить количество эпох или использовать `patience`.
- Использовать более лёгкую модель (YOLO11n вместо YOLO11s).

### Модель не обнаруживает объекты


**Признак:** на тестовых изображениях объекты не обнаружены или уверенность очень низкая (< 0.3).


**Решения:**

- Проверить разметку — открыть несколько txt-файлов и убедиться, что координаты корректны.
- Добавить данные — возможно, 200 изображений недостаточно для этого объекта.
- Снизить порог уверенности при инференсе: `model.predict(..., conf=0.25)`.
- Проверить `data.yaml` — убедиться, что пути и названия классов верны.

### Низкий mAP (< 0.5)


**Решения:**

- Проверить баланс классов — возможно, один класс сильно доминирует.
- Увеличить разнообразие данных.
- Проверить разметку — распространённая причина низкого mAP — неточные или ошибочные bbox.
- Попробовать большую модель (YOLO11s), если ресурсы позволяют.

### Ошибка нехватки памяти GPU (CUDA out of memory)


**Решение:** уменьшить batch: `batch=8` или `batch=4`. Или уменьшить `imgsz=416`.


## Перенос модели на Микродрон


Бортовой компьютер Микродрона имеет аппаратный NPU (нейросетевой ускоритель), который работает с форматом `.cvimodel`. Обученную модель нужно конвертировать из PyTorch в `.cvimodel` — это можно сделать самостоятельно.


Готовый пример — Google Colab-ноутбук [yolo_train_and_export.ipynb](https://git.sverk.io/tiny_control/edu/ml/-/blob/master/yolo_train_and_export.ipynb): он обучает модель и сразу экспортирует её в `.cvimodel`.


>

**Подсказка** Ноутбук покрывает весь цикл — от обучения до экспорта в `.cvimodel`, поэтому им удобно пользоваться целиком, без ручного запуска обучения из предыдущих разделов.


### Как устроена конвертация


Конвертация идёт в несколько этапов — все они выполняются ноутбуком автоматически:

- Экспорт обученной модели `.pt` в формат ONNX (вход 640×640).
- Преобразование ONNX в промежуточный формат `.mlir` с нормализацией изображения.
- Калибровка на ~200 изображениях из обучающей выборки — нужна для квантизации в int8.
- Сборка итогового `.cvimodel` под процессор `cv181x` бортового компьютера.

Для конвертации используется тулкит Sophgo tpu-mlir. Готовые команды каждого этапа уже прописаны в ноутбуке — менять их обычно не нужно.


>

**Примечание** Калибровочные изображения должны быть из того же набора, на котором обучалась модель, иначе точность после квантизации в int8 заметно упадёт.


### Шаг 1. Скопировать модель на дрон


Скопируйте готовый файл `.cvimodel` на бортовой компьютер:


```
scp your_model.cvimodel root@10.10.1.1:/root/

```


Или, если работаете по Wi-Fi после подключения к роутеру, укажите IP-адрес дрона в сети.


### Шаг 2. Запустить детектор


Детектор запускается командой на борту дрона:


```
/root/packages/yolo_detector your_model.cvimodel 3 0.3 0.3 1 1

```


Параметры команды:

- `your_model.cvimodel` — путь к файлу модели
- `3` — ID класса для обнаружения (зависит от вашей модели: 0 = первый класс, 1 = второй, и т.д.)
- `0.3` — порог уверенности объекта (`obj_thresh`): объекты с `score < 0.3` игнорируются
- `0.3` — порог NMS (non-maximum suppression): фильтрация перекрывающихся обнаружений
- `1 1` — дополнительные параметры (стриминг и публикация в ROS-топик)

>

**Подсказка** Подбирайте `obj_thresh` экспериментально. Значение 0.3 — хорошая стартовая точка. Если много ложных срабатываний — увеличьте до 0.5—0.7. Если объект плохо обнаруживается — уменьшите до 0.2.


### Шаг 3. Проверить стрим с обнаруженными объектами


На компьютере можно посмотреть видеопоток с отрисованными bbox:


```
ffplay -fflags nobuffer -flags low_delay -rtsp_transport udp rtsp://10.10.1.1:8554/stream

```


### Шаг 4. Получение обнаруженных объектов в Python-скрипте


После запуска `yolo_detector` результаты доступны через стандартный API:


```
from simple_offboard_py import SimpleOffboard

drone = SimpleOffboard()

# Детектор уже запущен на борту — просто читаем результаты
for det in drone.get_detections():
    print(f"{det.label} (score={det.score:.2f}) bbox=({det.x1},{det.y1})-({det.x2},{det.y2})")

```


Убедитесь, что модель работает корректно: запустите детектор при нескольких положениях объекта и проверьте, что результаты обнаружения стабильны. Если точность заметно хуже, чем при тестировании на компьютере, вероятно, условия съёмки (освещение, высота, угол) в датасете отличались от реальных — дособерите данные.
