# `rover_check/` — прогон агента ровера

Проверка того, что сделано на этапе 4 (`onboard/rover_agent.py`): скрипт стучится в
HTTP-контракт агента и печатает по строке на каждую проверку. Один файл, только
стандартная библиотека, никаких симуляций — просто список запросов и ответов.

Это **не** замена `tests/test_rover_agent.py` (те гоняют внутренности на заглушке
бэкенда). Здесь проверяется агент целиком, живым HTTP, включая тот случай, когда за
ним стоит настоящий ровер.

## Как запускать

**Без ровера, «сам себе стенд»** — скрипт поднимает `rover_agent.py --dry` на порту
8019, гоняет всё, включая переезд, и глушит агента:

```bash
python3 rover_check/check_rover.py
```

**По уже запущенному агенту** (тому, что смотрит на живой ровер, см. `RUN.md` 3Б).
Движение по умолчанию пропускается — ровер поедет по-настоящему:

```bash
python3 rover_check/check_rover.py --url http://127.0.0.1:8010
python3 rover_check/check_rover.py --url http://127.0.0.1:8010 --move
```

**Плюс железо мимо агента** — два GET прямо в родные API ровера, чтобы отделить
«агент виноват» от «ровер молчит»:

```bash
python3 rover_check/check_rover.py --url http://127.0.0.1:8010 --rover-ip 192.168.1.125
```

Код возврата 0 — всё прошло, 1 — есть провалы. На этой машине запускать полным путём
и с `PYTHONIOENCODING=utf-8` (см. `CLAUDE.md`).

## Что проверяется

| Раздел | Проверки |
|---|---|
| Контракт | `/status` отвечает 200 и содержит все поля (`ok role state cell since_move busy led`), роль `rover`, клетка — пара целых, чужой путь → 404 |
| Лента | `blink`, `on`, `off` — каждый режим отражается в `/status`; неизвестный режим → 403 |
| Отказы | несоседняя клетка → 403, `/drive` без `cell` → 400 |
| Движение | переезд в соседнюю клетку, подтверждение по `cell` и `state=idle`, дедуп повторного `command_id`, возврат в исходную клетку |
| Стоп | `/stop` → `state=stopped` (последней проверкой, чтобы оставить ровер стоящим) |
| Железо | `rover_control_api :8767` отвечает, `nav2_ready`, фрейм позы, метка карты; `rover_web :8765` отвечает |

## Что НЕ проверяется

- **Сторож (watchdog)** — требует 3+ секунды тишины при едущем ровере, на заглушке
  переезд мгновенный. Проверяется на площадке глазами: закрыть диспетчер на ходу.
- **409 «занят»** — на заглушке команда успевает отработать раньше, чем придёт вторая.
- **Точность заезда и калибровка сетки** — это не про контракт, а про `--map-x0/--map-y0/--map-yaw`,
  процедура в `RUN.md` 3Б.4.

## Что сейчас показывает живой ровер (29.07.2026)

На `192.168.1.125` прогон даёт 14 из 15 ОК, а провал — **ожидаемый**:

```
[ПРОВАЛ] Nav2 поднят — nav2_ready=False, поза во frame 'odom'
```

Оба порта живы, лента слушается, агент отвечает; Nav2 просто не запущен, и агент
поэтому честно отказывается ехать. Поднятие Nav2 — задача первого дня; после неё эта
строка должна стать `ОК`, и только тогда имеет смысл гонять `--move` на железе.
